# http-app/detail-cache.ts — 판단 기록

**정본** = `v2/app/packages/adapters/http-app/src/detail-cache.ts`. 명령은 `v2/app`에서.
규칙 원문 → `v2/docs/specs/C5-S1-조회저장과상세영속.md`(E-1~E-12), SRS FR-401·FR-504·§6.4.

등급: `[실행]` 실행 출력 / `[코드]` 코드를 읽었음 / `[대화]` 인용 가능한 사용자 발언 / `[문서]` 문서 하나 / `[미검증]`.

## 판단 1 — 조회/저장은 열거값이 아니라 두 테이블이다

**결정.** `Tag`(알아/몰라/적용모름)를 값만 `viewed`/`kept`로 바꾸지 않고 **열거 자체를 없앴다.**
저장 = `assets` 행의 존재(이미 있던 것), 조회 = `details` 행의 존재(신설).

**왜.** 두 사실은 **동시에 참일 수 있다** — 펼치고 담으면 둘 다, 카드에서 바로 담으면 저장만,
펼치고 안 담으면 조회만. 단일 `tag` 컬럼은 이 상태를 표현하지 못하고, 값만 갈아끼우면
첫 경우에서 한쪽이 조용히 소실된다. 사용자 지시는 "조회/저장으로 일원화" `[대화]`였고,
일원화의 올바른 형태가 열거 교체가 아니라는 것은 구현 중 내가 판단했다.

**뒤집으면 깨지는 것.** "상태 하나에 값 하나가 단순하다"며 `Engagement` 열거를 다시 만들면,
둘 다인 어휘를 표현할 수 없어 어느 한쪽을 버리게 된다. 버려지는 쪽은 화면에서 안 보인다 —
패널이 "조회한 것"에서 빠뜨리거나 "저장한 것"에서 빠뜨릴 뿐 에러가 없다.

**태그가 제거 가능했던 근거** `[실행]`(`corepack pnpm gate`가 이 상태로 exit 0):
`core/src/prompts/recommend.ts`가 LLM에 `Always set tag to "몰라"`를 지시하고 있었으므로
`Term.tag`는 항상 `"몰라"`였고, `summarize.ts`가 그 태그로 `known_terms`/`unknown_terms`를
갈랐으므로 `known_terms`는 **구조적으로 항상 빈 배열**이었다. `primer_known` 문구는 화면에
뜬 적이 없다. 즉 제거는 기능 손실이 아니라 죽은 회로 정리다.

**DG-17 분류** `[실행]`(`git log -S`): `TAGS`는 `0ac6e82`(C1, v1 무손실 이식), `knowledge` 테이블은
`cb664d8`(C2.1, FR-502용 선구현). 둘 다 **(a) 미완성**이고 (b) 되돌린 잔재가 아니다 —
삭제가 과거 회귀를 되살리지 않는다. (a)의 기본 처방은 "배선"이지만 축 폐기 결정이 우선했다.

## 판단 2 — 캐시 키는 어휘가 아니라 Prompt5In 전체다

**결정.** `input_key = SHA-256(길이접두어로 이은 Prompt5In 전 필드 + 프롬프트 버전)`.
`term_norm`은 표시·목록용이며 **조회 조건이 아니다.**

**왜.** `Prompt5Out.whymine`은 "왜 나에게 중요"라 세션 맥락(`topic`·`job_type`·`connection_hint`)에
의존한다 `[코드]`. 어휘로 캐시하면 다른 세션에서 **이전 세션의 내 맥락**이 나오고, 그것이
틀렸다는 걸 사용자가 알아챌 방법이 없다. 죽지 않고 잘못 동작하는 종류다.

**구분자를 안 쓰고 길이 접두어를 쓴 이유.** `topic`이 자유 입력이라 어떤 구분자든 본문에
나타날 수 있고, 그러면 서로 다른 입력이 같은 키로 접힌다. 음성 케이스가 게이트에 있다 `[실행]`
(`e2e-detail.mjs`의 "필드 경계가 섞이지 않는다"). NUL 구분자를 쓰지 않은 것은 SH-2(Write 도구가
이스케이프를 진짜 제어문자로 써 파일을 오염시킨 실측) 회피이기도 하다.

**프롬프트 버전을 키에 넣은 이유.** 넣지 않으면 상세 프롬프트를 개편해도 옛 본문이 영구히
반환된다 — 개편이 반영되지 않았는데 화면은 정상으로 보인다. 개편 시 `DETAIL_PROMPT_VERSION`을
올리는 것이 릴리스 절차의 일부다.

## 판단 3 — 캐시 조회는 게이팅보다 먼저 돈다. 순서가 곧 규칙이다

**결정.** 캐시 조회 미들웨어를 `installGating` **안에서** 상세 한도 미들웨어보다 먼저 등록한다.
히트면 `next()`를 부르지 않아 한도 미들웨어가 아예 돌지 않는다(E-5).

**왜 게이팅 파일에 뒀나.** 두 미들웨어의 상대 순서가 규칙 자체이기 때문이다. 라우트나 app.ts에서
따로 등록하면 등록 순서가 두 파일에 흩어지고, 순서가 뒤집혀도 **아무 게이트가 못 잡는다** —
캐시는 여전히 동작하고 한도만 조용히 차감된다. 사용자는 이미 지불한 생성에 두 번 청구된다.

**뒤집으면 깨지는 것.** "게이팅은 게이팅만 해야 한다"며 캐시 조회를 라우트로 옮기면, 라우트는
미들웨어 **뒤에** 돌므로 히트해도 카운터가 이미 올라간 뒤다. 관심사 분리가 맞아 보이는데
규칙이 깨지는 형태다. 옮기려면 한도 미들웨어에 "히트면 차감하지 않는다"는 조건을 넣어야 하고,
그러면 캐시 조회가 두 번 일어난다.

**이 규칙은 자동 검증이 없다** `[미검증]`. 캐시는 `gateUserId`(JWT)에 걸려 있는데 `e2e-pg`는
DEV `x-user-id` 부트라 신원이 null이고, `e2e-gate`는 JWT를 쓰지만 PG 상세 캐시를 안 태운다.
**순서가 뒤집혀도 지금 게이트는 초록이다.** 스펙 §9에 열린 항목으로 남겼다.

## 판단 4 — 비로그인은 캐시하지 않는다

`details.user_id`가 `users`를 참조하므로 익명 행은 만들 수 없고, CRUD도 익명은 401이다 `[코드]`.
경계를 넓히려면 FK부터 바꿔야 하며 그것은 "서버 저장은 계정 귀속"(Q-07)을 건드리는 결정이다.

## 그때 무엇을 근거로 삼았나 — 자기 신고, `[미검증]`

- **통째로 읽은 것** — `gating.ts`, `pipeline-routes.ts`, `app.ts`, `detail-machine.ts`,
  `useDetail.ts`, `keep.ts`, `primer.ts`, `usePrimer.ts`, `enums.ts`, `persistence-ports.ts`,
  `knowledge-repo.ts`(삭제 전), `asset-repo.ts` 앞부분, SRS §4.6·§6·§7.
- **안 읽은 것** — `pipeline-io.ts` 전문(`Term`·`Prompt4In`·`Prompt5In` 절만 읽었다),
  `session-repo.ts`, `migrate.ts` 본문(러너 동작은 주변 렌즈 보고로 대체).
- **브리핑** — 주변 렌즈 1대만 돌렸다. 현장 몫은 `tsc -b`로 대체했다 — 필수 필드 제거는
  컴파일러가 소비자를 전수 열거하므로 에이전트 보고(등급 2~4)보다 상위 증거다 `[실행]`.
  **브리핑이 계획을 바꿨다**: 베이스라인 수동 편집 조건(C3-S4b 선례)과 게이트 밖 스크립트
  2종을 그때 받았다. **브리핑 보고 2건은 내가 재측정해 뒤집었다** — `_shadow/` 부재 주장(리포
  루트에 실재), `usePrimer.ts:32` 캐스팅을 컴파일러가 못 잡는다는 주장(속성 자체를 없애면 잡힌다).
- **알고도 미룬 것** — E-5 자동 검증, `/detail` 스트리밍(FR-401 절반 미충족), 조회 목록 API(S2).
- **재현 명령** — `corepack pnpm gate`(exit 0) / `docker compose up -d --wait && corepack pnpm gate-db`(exit 0).

## 이 노트가 낡는 조건

- **S2 우측 패널이 붙으면** `DetailRepository`에 목록 조회가 생긴다 — 그때 `body`를 목록에서
  빼는 것(E-8)이 실제로 지켜지는지 확인할 것. 지금은 소비자가 없어 규칙만 있다.
- **`/detail`이 스트리밍이 되면** 판단 3의 "서버에서 원자적으로 저장"이 무너진다. 부분 본문을
  저장하지 않는 규칙(E-6)을 스트림 완료 지점에서 다시 세워야 한다.
- **익명 캐시가 필요해지면** 판단 4가 아니라 FK와 Q-07이 먼저다.
- **`gate-db`가 오래 안 돌면 이 노트의 exit 0은 낡는다.** 실제로 `e2e-gate.mjs`의
  `paste_text` 단언이 C3-S4b 이후 깨진 채 방치돼 있었고 이번에 발견됐다 `[실행]` — 체인 밖
  스크립트는 통과 여부를 사람이 봐야 한다.
