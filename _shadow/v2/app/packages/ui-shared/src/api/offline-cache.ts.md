# api/offline-cache.ts — 판단 기록

**정본** = `v2/app/packages/ui-shared/src/api/offline-cache.ts`. 명령은 `v2/app`에서.
규칙 원문 → `C4-S3-오프라인캐시.md`(DS3-2·DS3-3), 계약 §3-3(:156), `C4-데스크톱.md`(D-6·D-12).

등급: `[실행]` 실행 출력 / `[코드]` 코드를 읽었음 / `[대화]` 사용자 발언 / `[문서]` 문서 하나 / `[미검증]`.

## 판단 1 — 조율은 훅이 아니라 ApiPort 데코레이터다

**결정.** `withOfflineCache(api, store, onChange)`가 `listSessions`·`getSession`만 감싸고 나머지는
명시 위임한다. `useSessionSync`는 한 줄도 안 바뀌었다 — 훅은 자기가 캐시를 쓰는지 모른다.

**왜.** ① 폴백 목록이 `nextCursor: null`이라 "더 보기"가 저절로 사라진다 — 훅에 오프라인 분기를
넣을 일이 없다. ② 쓰기 메서드를 **안 감싸는 것만으로** D-6(오프라인은 열람만)이 구조로 성립한다 —
검사가 아니라 부재로 막는다(DG-3 계열). ③ 노드에서 목 ApiPort로 검증된다 `[실행]`(e2e-offline
15/15, e2e-auth-client 선례). 훅 안에 넣었으면 React 없이 검증할 방법이 이 리포에 없었다.

**명시 위임인 이유** `[코드]`: HttpApiClient는 클래스라 스프레드로 메서드가 복사되지 않는다
(프로토타입 메서드는 own property가 아니다). 반환 타입 ApiPort가 위임 누락을 tsc에서 잡는다 —
ApiPort에 메서드가 늘면 이 파일이 컴파일로 깨지는 것이 **의도**다.

**뒤집으면 깨지는 것.** "훅에서 직접 캐시를 읽는 게 명시적"이라는 이유로 훅에 넣으면, off(비로그인,
S-1)와 오프라인이 한 파일에서 얽히고 — 지금도 네트워크 실패가 빈 목록과 구분 안 되던 화면이다
`[코드]` — 검증은 React 의존이 된다.

## 판단 2 — 첫 페이지(무검색·무커서)만 캐시한다

검색·커서 요청 결과로 목록 캐시를 덮으면 "마지막으로 본 필터"가 오프라인의 정본 행세를 한다.
e2e에 음성 케이스로 박았다 `[실행]`("검색·커서 결과는 캐시를 안 덮는다").

## 판단 3 — auth는 원본 클라이언트를 쓴다 (tsc가 잡았다)

데코레이터는 ApiPort만 반환하므로 `useAuth({auth: 데코레이터})`가 타입 오류였다 `[실행]`
(TS2739 — AuthPort의 login/refresh/logout 없음). 고치면서 확인한 것: 로그인·재발급이 캐시를
지나면 안 되는 게 맞다 — **타입이 이 분리를 강제한다.** journey의 /config도 같은 이유로 원본을 쓴다.

## 곁가지 — shell-bridge.ts 분리

이 데코레이터의 조립·locale 동기화·로그아웃 캐시 삭제가 journey.tsx에 쌓여 302행(>300 상한)이
됐다 `[실행]`(게이트 실패). 예외 등록 대신 `app/shell-bridge.ts`(useShellBridge)로 갈라냈다 —
화면 전환(여정)과 능력 배선(다리)은 다른 책임이다. 게이트가 분리 시점을 정확히 알려 준 사례.

## 그때 무엇을 근거로 삼았나 — 자기 신고, `[미검증]`

- **읽은 것** — ApiPort 전문, useSessionSync 반환 표면(브리핑 + 발췌), SessionList off/empty 렌더.
- **안 읽은 것** — useSessionSync 본문 전량(브리핑 보고로 대체 — off가 실패 시 안 바뀐다는 실측 포함).
- **실행 확인** — e2e-offline 15/15(음성 7건 포함), 게이트 256 PASS, 창 재빌드 캡처,
  폰트 로드 실측(별건이지만 같은 커밋 — `Pretendard Variable/loaded`, CDN 0).
- **창 안 오프라인 전체 실측은 미완** — 데스크톱 로그인(콘솔 등록, 사용자 킵)에 걸려 있다.
  기계 검증은 데코레이터 e2e까지다.
- **위치** — C4 S3 커밋.

## 이 노트가 낡는 조건

- **웹 IndexedDB 구현이 생기면** 이 데코레이터는 그대로 쓰이고 store만 바뀌는 것이 설계 검증이 된다.
  데코레이터를 웹 전용으로 복제하고 싶어지면 그것이 D-12 위반 신호다.
- **listAssets까지 캐시하게 되면**(S4에서 판단) 감싸는 경로가 셋이 된다 — "읽기 두 경로만"이라는
  이 노트의 서술이 낡는다.
- **오프라인 쓰기 큐가 필요해지면** 계약 §3-3(쓰기는 online-only)부터 바꿔야 한다. 이 파일이
  아니라 계약이 먼저다.
