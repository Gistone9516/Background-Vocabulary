# Background-Vocabulary — 배경노트 (Vock note)

AI 탑다운 학습 시대. 비전공자가 알아야 할 전문 배경어휘 지식을 뽑아주는 서비스

막연한 생각을 가진 사용자가 "설명(표현)하지 않고도" 클릭·재인만으로 의도를 결정화해, 자기 상황에 맞는 배경지식 어휘를 얻는 도구. 제품 핵심 축 = **표현(articulation) 비용 면제** 단일 축.

## v2 방향 (2026-07-20 결정)

- 폼팩터: 크롬 확장 → **웹사이트 + 크로스플랫폼 데스크톱 앱**. 데스크톱은 고유 기능 추가.
- 방법론: 소프트웨어 공학 명세 절차(요구사항 명세 → 아키텍처 설계 → 상세설계 → 구현 → 테스트). 디자인 패턴·계층 분리 기반의 유지보수 가능한 코드, 적층형 코딩 금지.
- v1 기획은 **요약 없이 원문 그대로 승계**(승계원장). 디자인 컨셉은 v1 유지(덜어내고 차분하게), 더 나은 안은 변경 후보로 검토.
- 결제·수익 모델은 사이드탭 제약 위 설계라 v2에서 재설계. free 티어 광고 BM 확정(2026-07-20), pro는 광고 없음.
- 백엔드 자산(Workers+Hono, D1 엔타이틀먼트, 서버 JWT, Google SSO, 프롬프트 파이프라인)은 폼팩터 무관이므로 재사용 우선 검토.

## 인프라 목표 2단계 (2026-07-28 결정)

1. **1차 = AWS 배포.** 서버리스 구성(Lambda Function URL 스트리밍, Aurora Serverless v2 + Data API, S3/CloudFront)으로 제품을 실제로 띄운다. 체크리스트 = `v2/app/DEPLOY.md`.
2. **2차 = 리눅스에서 직접 서버 구축·운영.** 1차 완료 후 별도 트랙.

2차를 세운 이유: 서버리스는 운영할 OS 계층이 없다. Lambda에는 SSH도, 패키지 관리도, 서비스 데몬도 없어서 관리형 서비스에만 기대면 리눅스 서버 운영 실력이 늘지 않는다. 1차에서 얻는 것(IaC, IAM, VPC, 관측, 비용)과 2차에서 얻는 것(OS, 프로세스, 네트워크, 보안 하드닝)이 다르므로 둘 다 한다. 무엇을 어디에 올릴지는 1차를 끝내고 정한다.

## 현재 상태

- v1 동결 완료(최종 커밋에 계약 §9 포트원 Phase 1 SoT, 테스트용 pro 토글 포함).
- **설계 3각 확정**: SRS v1.0(요구) · ADR v1.0(기술 — AWS 전면·Tauri·Vite+Astro·pnpm) · 인터페이스계약 SoT v2.0(상세설계, 4렌즈 적대 검토 반영). 승계원장으로 v1 기획 무손실 승계, 설득 논거 정본화.
- **C1 완료(뼈대)**: `v2/app/` pnpm 모노레포 스캐폴딩 + v1 shared/core·프롬프트 무손실 이식 + 경계 게이트 3중(TS 레퍼런스·portability-guard·boundary-check) + 코드규약 검사(파일 크기·프롬프트 패리티) + local mock e2e(`/classify→/next→/recommend`) 관통. 전 게이트 PASS.
- **C2 완료(서버 전량)**: 영속(PG·SqlRunner 포트) → 인증(자체 JWT·Google OAuth PKCE) → 게이팅(티어·한도·고위험) → 실 공급자(DeepSeek SSE·Tavily·Upstash) → aws 부트(DataApiSqlRunner·streamHandle). 로컬 e2e 38건 + 실키 스모크 7/7 통과. 실 AWS 배포만 핸즈온으로 남음(`v2/app/DEPLOY.md`).
- **C3 진행 중(웹·랜딩, S5a·S4b까지)**: ui-shared 화면 계층 + web Vite SPA. 반응형 2열 셸과 치수 정책 확정(길이는 rem, 글자는 창 크기에 반응하지 않음, 레이아웃만 반응, 입력창은 불변 위치, 기준값은 `ui-shared/styles/scale.css` 단일 지점). `entry → classify → 좁히기 → 난이도 → 어휘 카드 스트리밍 → 카드 상세`가 실제 서버와 관통한다. 좁히기·어휘 생성·카드 상세를 각각 순수 상태 기계로 분리해 서버 없이 전이 67개 케이스를 게이트에서 검증한다.
- **S4 완료**: 담기와 담은 어휘 화면, 메인 AI에 붙여넣을 기본 정리(무비용, 서버 없이). 담기는 화면 상태로만 유지하고 서버 저장은 S5로 미뤘다.
- **S5a 완료(로그인)**: PKCE OAuth·토큰 저장·401 1회 재발급. 로그인은 관문이 아니라 비로그인으로도 전 여정이 돈다. `client_id`가 없으면 버튼 자체가 뜨지 않아 콘솔 등록 전에도 화면이 멀쩡하다.
- **S4b 완료(AI로 더 정리)**: `/summarize`가 완성 문장(`paste_text`) 대신 구조(`PrimerDoc`)를 돌려주고 붙여넣을 본문은 클라가 조립한다. 그래야 형식·로케일을 바꿀 때 서버를 다시 부르지 않는다. pro 전용이며, 실패하거나 잠겨도 무비용 기본 정리는 그대로 남는다.
- **S5-1 완료(세션 저장·재개)**: 좁히기가 매 턴 서버에 저장되고, 사이드바에서 이전 탐색을 눌러 이어서 진행한다. 재개는 `/classify`를 다시 부르지 않아 주간 한도를 깎지 않는다. 저장은 로그인한 사용자만 하고, 비로그인 여정은 그대로 돌되 저장되지 않음을 사이드바가 알린다.
- **S5-2 완료(프로젝트·연결 턴)**: 사이드바에서 프로젝트를 만들고 고르면 세션 목록이 그 범위로 좁혀지고 새 탐색이 거기 배속된다. 프로젝트에 담은 어휘가 있으면 좁히기 종료 직전 연결을 묻는 턴이 한 번 끼고, 관련 없거나 실패하면 그대로 넘어간다. 중복 제외는 서버가 세션에서 프로젝트를 찾아 처리한다(클라가 목록을 실어 보내지 않는다).
- **S6 완료(랜딩)**: Astro 정적 랜딩(JS 0)에 설득 콘텐츠 한 페이지. 카피는 사용자 레드펜 확정본이고, 가격·한도 수치는 문구에 넣지 않는다(정해져도 운영 설정에서 빌드 시점에 주입한다). 게이트가 산출물 HTML에서 그것을 검사한다. 랜딩은 앱 코드를 하나도 가져오지 않고 디자인 토큰 **변수만** 공유한다 — 앱 스타일시트를 가져왔더니 두 절이 사라진 것처럼 보인 일이 있었고(렌더는 되어 있었다) 그 뒤로 게이트가 진입점 이름 단위로 막는다.
- 다음 = **C4 데스크톱**(Tauri v2). 상위 스펙 `v2/docs/specs/C4-데스크톱.md` 확정, 슬라이스 S1~S5 계획됨. 빌드 툴체인(Rust + MSVC + Windows SDK)은 설치해서 실제로 링크되는 것까지 확인했다. 그다음 C5.
- **S1~S5 정합 감사(6렌즈 병렬)**: 지적 144건. 그중 실행으로 확인된 7건을 수정했다 — 되돌리기가 쓴 예산을 전액 돌려주던 것(스펙 정반대), 유료 사용자가 무료 한도를 받던 것, 상세 한도 402가 분류되지 않아 잠김 화면이 도달 불가였던 것, 프롬프트가 지시하지 않는 필드를 응답 가드가 요구해 실키에서 /summarize가 항상 깨지던 것, 연결 턴의 답이 저장도 사용도 되지 않던 것, 연결 턴 대기 화면과 무효 버튼. 나머지는 미검증으로 남겼고 산출물을 `v2/docs/감사-2026-07-29/`에 보존했다. **그 "137건"은 재현 자료 없이 적은 숫자였다** — 살아남은 산출물은 렌즈 4개·지적 30건이고 두 렌즈의 출력은 세션 임시 디렉터리와 함께 사라졌다. 목록을 위에서부터 훑지 않고 그 영역을 건드릴 때 꺼내 보는 참조로 다룬다(사용자 결정 2026-07-30): 재측정 표본 7건 중 3건이 이미 뒤 슬라이스가 지나가며 해소돼 있었고, 목록을 그대로 믿고 고치면 없는 것을 찾거나 다른 이유로 바뀐 것을 되돌린다.
- **S5-3 진행 중(4개 언어)**: ①전달 완료 — 클라가 `outputLocale`을 실어 보낸다(붙이는 자리는 한 곳). ②이식 실측 완료 — v1 244키 대조 결과 74건 이식 가능, 27건 신규(초안 작성됨, 일본어·중국어 검토 필요), 2건 죽은 키. **이름이 같아도 한국어 문구가 다른 키가 11건 있어 자동 이식을 막았다.**
- **S5-3 ②-a 완료(언어 선택과 영속)**: 헤더에서 언어를 고르면 저장되고, **어휘·상세·프라이머 생성 결과와 진입 화면 예시 칩이 그 언어로 나온다.** UI 문구는 아직 한국어다(②-b). ①이 실제로는 죽어 있었다 — 웹 셸이 `getOutputLocale`을 넘기지 않아 전 사용자가 조용히 한국어로 고정돼 있었고, e2e가 자기 손으로 값을 주입해 검사하는 바람에 초록이었다. 선택 사항이던 그 옵션을 **필수로 바꿔** 빠뜨린 셸이 타입 검사에서 막히게 했고, 막히는지를 일부러 실패시켜 확인했다. 남은 것 = ②-b(UI 문구 4개 언어) · ③`check-i18n` 게이트.
- **S5-3 ②-b 완료(UI 4개 언어)**: 화면 문구 101키가 ko/en/ja/zh로 나온다. 표는 `Record<StringKey, string>`로 타이핑해 **키 누락을 타입 검사가 막고**, 폴백 분기가 생길 자리를 없앴다(v1은 `?? ko[key] ?? key`로 누락을 정상처럼 보이게 했다). 이식분 64건은 v1 원문 그대로이고 AI가 쓴 37건은 `strings.origin.ts`가 세어 두 근거 등급이 코드에서 구별된다. **어느 문구를 어디서 가져왔는지가 지워지지 않는 것이 요점이다.** 이식은 키 이름이 아니라 v1의 옛 이름으로 대조했다 — 개명된 키 11개를 이름으로 맞추면 v1의 사람 번역이 AI 번역으로 조용히 대체되고, 결과물도 정상적인 문장이라 어디에도 걸리지 않는다.
- **S5-3 마무리(S-31·S-35)**: 붙여넣을 본문의 라벨이 `PrimerDoc.locale`을 따른다 - 화면 언어를 바꾸는 것과 메인 AI에게 보낼 글의 언어를 바꾸는 것은 다른 일이다. 그리고 화면이 서버의 오류 문구를 그대로 띄우지 않고 `error` 코드를 문구 키로 옮긴다. 서버는 로케일을 모르고 한국어만 보내므로 그대로 띄우면 영어 화면에 한국어 오류가 떴다. 매핑을 `Record<ApiError["kind"], StringKey>`로 둬서 **오류 종류를 추가하고 문구를 정하지 않으면 빌드가 실패한다** - 일부러 종류를 하나 넣어 막히는 것을 확인했다. 화면 세 곳에 복제돼 있던 캐스트 폴백도 함께 사라졌다.
- 적층형 방지 규칙을 `v2/docs/코드규약.md` 6~9절에 명문화했다: 동작 규칙은 ID와 근거와 테스트를 갖고, 버그는 고치기 전에 분류하고, 막을 수 있으면 검사하지 않고, 큰 변경은 스펙이 먼저다.
