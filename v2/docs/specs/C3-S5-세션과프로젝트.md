# C3 S5 스펙 — 세션·프로젝트·연결 턴·4개 언어 (SoT §3-3·§5에서 파생)

> 상위 = [C3-웹랜딩.md](C3-웹랜딩.md). 앞 = [C3-S4b](C3-S4b-프라이머.md) · [C3-S5a](C3-S5a-로그인.md).
> 규칙: S-1~S-37 (37건)

## 0. 범위

- **포함**: 세션 서버 저장·재개 · 사이드바 실데이터(목록·검색·핀·삭제/실행취소) · 담기 서버 동기화 · 어휘 자산 목록 · 프로젝트 CRUD와 세션 배속 · 연결 턴(`/relate`) · 프로젝트 kept 중복 제외 · UI 4개 언어.
- **제외**: 익명 세션의 로컬 저장과 로그인 승격 업로드(SoT §3-3 소유권 규칙 — 별도 슬라이스) · 튜토리얼(FR-951) · 마인드맵(FR-312, C5) · 구조화 구체화 아키네이터(FR-607, C5).

**라우트는 C2에서 전부 구현돼 있다.** `/sessions`·`/assets`·`/projects`·`/knowledge`·`/relate` 모두 있다(`http-app/src/routes/crud-routes.ts`, `pipeline-routes.ts`). 라우트를 새로 만들려 하고 있다면 이미 있는 것을 못 찾은 것이다.

**단 서버 작업이 한 건 있다 — FR-706 dedup(S-24).** SoT §3-3이 "dedup 책임은 서버다, 클라 전달 의존 금지"라고 못박았고 `AssetRepository.termNormsByProject`가 그것을 위해 만들어져 있으나(`persistence-ports.ts:46` 주석이 "서버가 exclude에 병합"이라 적고 있다) **호출자가 0건이다.** `/recommend` 라우트는 `repos`를 받지 않아 병합이 일어날 자리가 없다. S5-2에서 그 자리를 만든다.

**저장 시점을 정하는 코드도 이미 있다.** 상태 기계가 매 턴 `saveSnapshot` 명령을 내고(`narrow/machine.ts:107,163,216`, 고위험은 내지 않는다 — S2 B-2), 생성이 settle하면 `completeSession`을 낸다(`terms/machine.ts:50`). 이펙트 포트와 훅 옵션(`useNarrow.saveSnapshot?`·`useTerms.onComplete?`)도 있고 `e2e-narrow`가 발행 자체를 이미 검증한다(B-2·B-13). **비어 있는 것은 `App.tsx`가 그 두 콜백을 넘기지 않는 것뿐이다.** 저장 시점 판단을 새로 만들지 말 것. 상태 기계는 건드리지 않는다.

## 1. 하위 순서

의존이 순서를 강제한다. 연결 턴은 프로젝트를, 프로젝트는 세션을 필요로 한다.

| 단계 | 범위 | 규칙 |
|---|---|---|
| S5-1 | 세션 저장·재개·사이드바 목록·담기 동기화 | S-1~S-9·S-20~S-23 · **구현 완료** |
| S5-2 | 프로젝트·연결 턴·중복 제외 | S-10~S-15·S-24~S-26 · **구현 완료** |
| S5-3 | 4개 언어 (①전달·②-a 선택과 영속 **완료** / ②-b UI 문구 4개 언어·③키 집합 게이트 남음) | S-16~S-19·S-30~S-33 |

②-a까지로 **생성 출력**(어휘·상세·프라이머)과 진입 화면 예시 칩이 선택한 언어로 나온다. **UI 문구는 아직 한국어 고정이다** — `strings.ts`가 `ko` 하나뿐이라 S-16이 미구현이고, 따라서 S-17이 요구하는 "UI와 생성 출력이 같은 값"은 생성 쪽 절반만 만족한 상태다. ②-b가 그 절반을 메운다.

| S-7 | 담기는 화면 상태를 먼저 바꾸고 서버는 뒤따른다. 서버 실패가 담기를 되돌리지 않는다 | FR-601. 담기 반응이 왕복 시간에 묶이면 카드 훑기가 끊긴다 |

| S-9 | 목록은 커서 페이지네이션으로만 읽는다. 전량 조회 경로를 만들지 않는다. 커서는 불투명 문자열로 다루고 클라가 다시 정렬하지 않는다 | SoT §5 Data API 1MB 상한. 정렬은 서버가 `updated_at DESC, session_id DESC`로 정한다(`session-repo.ts:112`) — 클라가 따로 정렬하면 두 정렬이 어긋난다 |
| S-20 | `NarrowSnap`은 재개에 필요한 것을 전부 담는다: 현재 질문·선택지·답변에 더해 `classify`(Prompt1Out)와 좁히기 플래그(`simplify`·`usedUndo`·`confidence`) | FR-701 "이어서 진행". `SessionRec`의 컬럼만으로는 `NarrowCtx`를 못 만든다 — `search_locale`이 없어 재개 후 추천이 잘못된 로케일로 나가고, 첫 질문이 없어 되돌리기 기준점이 사라지고, `usedUndo`가 없으면 재개할 때마다 되돌리기가 새로 생긴다. `narrow`는 JSONB라(`0001_init.sql:42`) 스키마 변경이 아니다 |
| S-21 | `SessionRec`의 스칼라 컬럼(`area`·`job_type`·`domain_risk`·`user_condition`)은 저장할 때 `classify`에서 파생한다. 재개할 때 그 컬럼들을 되읽어 `NarrowCtx`를 조립하지 않는다 | 같은 값이 두 곳에 있으면 정본을 정해야 한다. 컬럼은 목록 필터·검색용 색인이고 정본은 `classify` 하나다. 양쪽에서 읽으면 어느 쪽이 맞는지 아무도 모르게 된다 |

### 2-3. 언어

| # | 규칙 | 근거 |
|---|---|---|
| S-16 | `tr`는 로케일을 받는다. 현재의 `ko` 하드코딩을 걷어낸다 | FR-952. `strings.ts`가 `ko` 상수를 직접 읽고 있어 다른 언어가 들어갈 자리가 없다 |
| S-17 | 로케일은 영속되고 UI와 생성 출력에 같은 값이 쓰인다 | FR-952. 둘을 따로 두면 한국어 UI에 영어 카드가 뜬다. 값이 하나면 어긋날 수 없다 |
| S-18 | 4개 언어 문구는 v1 `i18n.ts` 원문을 그대로 옮긴다. 새로 번역하지 않는다 | 코드규약 §7 이식 기준. 문구는 무손실 이식 대상이다 |
| S-19 | v2에서 새로 쓴 문구는 4개 언어를 갖춰야 한다. 빠진 키를 `ko`로 조용히 폴백하지 않는다 | FR-952(정책 문구 전 언어 정본). 폴백은 누락을 정상으로 보이게 만든다. 게이트가 로케일별 키 집합 일치를 검사한다. v1 `t()`는 ko 폴백을 하므로 그 부분은 이식하지 않는다 |
| S-30 | 출력 로케일은 생성 요청 본문 조립 한 곳에서 붙인다. 엔드포인트마다 손으로 붙이지 않는다 | 서버는 본문의 `outputLocale`만 보고 생성 언어를 정한다(`readLocale`). 엔드포인트마다 붙이면 새로 생긴 엔드포인트가 조용히 "ko"로 떨어진다 |
| S-32 | `HttpApiConfig.getOutputLocale`은 선택 사항이 아니라 필수다. 기본값을 두지 않는다 | 선택 사항이던 동안 웹 셸이 이걸 넘기지 않은 채로 나갔고 전 사용자가 조용히 `"ko"`로 고정됐다. e2e는 자기가 값을 주입해 검사하므로 초록이었다(`e2e-auth-client.mjs:144`). 필수로 두면 빠뜨린 셸이 `tsc --noEmit -p packages/web`에서 막힌다 — 잊을 수 있는 자리를 없앤다(코드규약 "검사보다 불가능") |
| S-33 | 로케일의 정본은 주입된 `LocaleStore`이고, React 상태는 다시 그리기 위한 사본이다. 요청 경로는 저장소를 매 요청 직접 읽는다 | 값을 클라이언트 생성 시점에 붙들면 언어를 바꿔도 앱을 새로 띄우기 전까지 옛 언어로 생성된다. 반대로 React 상태를 읽게 하면 로케일이 클라이언트 memo의 의존성이 되어, 언어를 바꿀 때마다 클라이언트가 새로 생기고 `/config` 재호출과 세션·프로젝트 재구독이 딸려온다 |
| S-34 | 화면에 뜨는 라벨을 프로그램 판정의 열쇠로 쓰지 않는다. 연결 턴의 "관련 없어요"는 선택지에 붙은 표식으로 판정하고, 문자열 비교로 판정하지 않는다 | `machine.ts`의 `NO_RELATION`이 한 문자열로 네 일을 겸한다 — 화면 라벨, 동일성 필터(`picked.filter((l) => l !== NO_RELATION)`), 서버로 가는 history 라벨, `e2e-narrow`의 단언 2건. 번역하면 필터가 조용히 어긋나고, 테스트는 ko로만 돌아서 안 잡힌다. 같은 검사를 로케일별로 늘리는 것은 해법이 아니다 — 로케일이 늘 때마다 필터가 늘어난다 |

| S-36 | 없는 키를 요청하면 예외를 던진다. 조용한 기본값을 두지 않는다 | S-19의 타입 강제는 컴파일 타임이다. 캐스트나 동적 키로 런타임에 키가 비는 경로가 남는데, 거기서 빈 문자열이나 ko를 돌려주면 S-19가 막으려던 상태가 그 구멍으로 되돌아온다. `useOutputLocale`이 컨텍스트 부재 시 예외를 던지는 것과 같은 판단이다(`locale.tsx`) |

| S-31 | 사용자가 복사해 가는 본문(프라이머)의 라벨은 UI 언어가 아니라 `PrimerDoc.locale`을 따른다 | 그 글은 메인 AI에게 보낼 것이지 화면 장식이 아니다. v1에는 대응 원문이 없다 — FR-604가 산문 템플릿을 항목형으로 바꿔서 `sum_*`는 이식 대상이 아니다. 따라서 신규 4개 언어 문구이며 사용자 확인이 필요하다 |

## 6-1. S5-3 이식 실측 (②단계 착수 자료)

> **판단 배경은 `_shadow/v2/app/packages/ui-shared/src/i18n/strings.ts.md`에 있다**(VF-22).
> 이 절이 2026-07-30까지 담고 있던 5행 표는 합계가 111이었으나 v2 키는 102개였다. 그 표를 따르면
> B갈래를 이식 가능으로 분류해 자동으로 아래 §6-2의 결정을 위반한다. 아래가 실측이다.

**수를 갈래 이름으로 쓰지 않는다.** B와 C가 둘 다 11개이고 `A+B`와 `A+C`가 둘 다 64가 되므로,
갈래는 항상 글자로 부른다.

재현 — `v2/app`에서:
```
node packages/scripts/measure-i18n-port.mjs
```

| 갈래 | 구분 | 수 | 처리 |
|---|---|---|---|
| **A** | 이름·한국어 모두 일치 | 53 | v1 en/ja/zh 그대로 이식 |
| **B** | **이름은 같은데 한국어가 다름** | **11** | **v2가 정본(§6-2). v1 번역은 옛 한국어의 것이라 그대로 쓸 수 없다** |
| **C** | v2에서 **개명**됐고 한국어는 일치 | 11 | v1의 **옛 이름**으로 이식. 전량 매핑은 위 명령의 `=== C 개명 매핑 전량 ===` 절 |
| **D** | v1에 이름도 문구도 대응 없음 | 27 | en/ja/zh 신규 작성. **이 중 `handoff_title`·`handoff_next`는 소비처 0이므로 삭제**(S2 임시 화면이 S3로 교체되며 죽었다) |

합계 102 = v2 키 총수. **이 합이 맞는 것은 항등식이므로 증거가 아니다** — 스크립트가 키를 네 갈래로
분할하기 때문이다. 실제 교차 검증은 스크립트가 출력하는 5건이며, 이름 집합의 교집합을 따로 세어
`A+B`와 맞추는 것이 그 핵심이다(A·B는 문구 비교로 갈리므로 어긋날 수 있다).

**새 번역이 필요한 키 = B 11 + (D 27 − 죽은 키 2) = 36건.** 이것은 상한이다 — 이름도 바뀌고
한국어도 손댄 키는 스크립트가 D로 떨어뜨리므로, v1에 번역이 있는 키가 D에 섞여 있을 수 있다.

**이름 일치를 이식 근거로 삼지 않는다.** 이름이 같아도 문구가 다르면 다른 문구이고(B), 이름이
달라도 문구가 같으면 같은 문구다(C). 이름으로 대조하면 C가 D로 떨어져 **v1의 사람 번역이 AI
생성 번역으로 조용히 대체된다.** 결과물도 정상적인 문장이라 화면·게이트 어디에도 걸리지 않는다.

## 6-2. S5-3 ② 신규 문구 초안 (D갈래 27건)

**B갈래는 v2 문구를 정본으로 확정한다(사용자 결정 2026-07-30: "v2가 더 직관적이네").**

그 결과 **B갈래 11건 전부가 새 번역 대상이다.** `refusal_title`·`relate_lead`는 v1과 뜻이 달라
완전 신작이고, 나머지 9건도 **v1 번역을 그대로 쓸 수 없다** — `sessions_search_ph`(세션→탐색),
`terms_loading`(가져오는→고르는), `sessions_empty`(기록 없음→이어갈 것 없음)처럼 단어가 바뀌었으므로
번역도 바뀐다. v1 번역은 출발점이지 결과물이 아니다.
따라서 B갈래 11건도 아래 초안과 **같은 근거 등급**이며 검토 대기 집계에 들어간다(S-37).

## 7. 열린 항목

- 익명 세션의 로컬 저장과 로그인 승격 업로드(SoT §3-3 소유권 규칙). S-1이 이번 범위에서 뺀 것이며 별도 슬라이스로 다룬다.
- FR-704의 세션 선택 UI "최대 크기 정량 기준"(레드펜). 좁은 화면은 기존 드로어로 충족되나 넓은 화면 기준은 미정.
- **로케일의 서버 영속(기기 간 공유).** `users.locale` 컬럼은 `0001_init.sql:8`에 있고 주석이 FR-952의 "크로스 플랫폼"을 가리키지만, 지금 그 컬럼에 닿는 코드가 없다. `user-repo.ts:34`의 `SELECT *`가 행은 가져오는데 `toUser`가 버리고, INSERT는 DB 기본값에 기댄다. 그리고 `UserRecord`에 `locale` 필드가 없고 `auth-ports.ts`에 쓰기 메서드 자리도 없다. 무엇보다 **서버→클라 로케일 전달 채널이 계약에 없다** — `/auth/google` 응답은 `{ email, tier }`뿐이다(`인터페이스계약-v2.md:135`). 즉 이건 계약 변경이라 스펙이 먼저다. 지금 즉흥으로 붙이면 서버 값과 `LocaleStore` 사이에 우선순위 규칙이 없는 로케일 정본 2개가 생긴다. 현재 상태는 **기기 단위 영속**이며 그것이 의도된 범위다.
- ~~`Difficulty`가 한국어 리터럴로 서버에 가는 문제~~ — **해당 없음.** 표시와 전송이 이미 갈려 있다: `DifficultyScreen.tsx`의 `LEVELS`가 `{ key: Difficulty; name: StringKey; ... }`이고 `key`가 전송값, `name`이 문구 키다. ②-b에서 손댈 것은 `diff_*` 값의 3개 언어뿐이다. (2026-07-30 브리핑이 이 항목을 반박했다. 이 자리에 적혀 있던 위험은 실재하지 않았고, 진짜 위험은 `NO_RELATION`이었다 — S-34.)
- **프라이머 본문의 하드코딩 한국어.** `kept/primer.ts`의 `ASK` 상수와 섹션 라벨(`"하려는 일"`·`"조건"`·`"분야"`·`"참고 맥락"`·`"이미 아는 어휘"`)이 문자열 테이블 밖에 있다. S-31이 요구하는 "프라이머는 `PrimerDoc.locale`을 따른다"는 이것들을 키로 올리기 전에는 만족할 수 없다. 또한 `buildBasicPrimer`·`primerFailure`는 `doc`을 받지 않으므로 로케일을 인자로 받아야 한다.
- ~~`doneNotice`가 훅으로 못 먹는 문제~~ — **해소.** 훅이 닿지 않는 호출부는 전 저장소에 4곳뿐이다(`App.tsx`의 `doneNotice` 2줄, `primer.ts` 2줄, 2026-07-30 실측 — 나머지 103곳은 컴포넌트 안이다). 그 4곳은 `trIn(locale, key)`을 직접 쓰고 로케일을 인자로 받는다. `trIn`이 존재하는 이유가 이 4줄이다.
