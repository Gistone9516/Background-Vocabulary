# C3 S6 스펙 — 랜딩 (Astro 설득 콘텐츠, FR-954)

> 상위 = [C3-웹랜딩.md](C3-웹랜딩.md). 앞 = [C3-S5](C3-S5-세션과프로젝트.md).
> 규칙: L-1~L-11 (12건 — L-4b 포함)

## 0. 범위

- **포함**: `packages/landing/`(Astro 정적 사이트) · 설득 콘텐츠 한 페이지 · 앱으로 가는 진입 링크 ·
  게이트에 랜딩 등록 · 배포 경로 분할 결정.
- **제외**: 온보딩(L-10) · 광고 실집행과 CMP(L-11) · 랜딩 다국어(L-6) · 블로그·가이드 등 추가 페이지.

**상위 스펙의 요구 하나가 지금 거짓이다.** `C3-웹랜딩.md` §1-4는 "portability-guard의 PROMPT_ROOTS에
세 패키지를 등록해 게이트로 강제한다"고 적었으나 실제 등록은 `ui-shared`·`web` 둘뿐이다
(`packages/scripts/portability-guard.mjs`). S6이 그 세 번째를 채운다.

## 1. 왜 Astro인가 — 이것이 제약을 만든다

SEO 때문이 아니다. `ADR-아키텍처결정.md` ADR-002:

> GPTBot·ClaudeBot 등 AI 크롤러는 JS를 실행하지 않고 원본 HTML만 파싱 — CSR SPA로는 AI 검색·챗봇
> 인용 채널에서 완전히 불리. Astro는 JS 0 정적 HTML + 필요한 곳만 React 아일랜드.

**목적이 "AI가 읽을 수 있는 HTML"이므로 JS를 넣는 순간 목적이 사라진다.** 아일랜드는 허용된 도구지
기본값이 아니다. 이 문장이 L-1의 근거이고, S6에서 아일랜드를 하나도 쓰지 않아도 되는 이유다.

## 2. 동작 규칙

| # | 규칙 | 근거 |
|---|---|---|
| L-1 | 랜딩은 JS 0 정적 HTML로 낸다. 그 페이지에 실제 상호작용이 없으면 React 아일랜드를 쓰지 않는다 | ADR-002(위 인용). 아일랜드를 기본으로 쓰면 AI 크롤러 노출이라는 목적이 조용히 사라진다. 상호작용이 필요해지면 그때 그 자리만 아일랜드로 만든다 |
| L-2 | 랜딩은 `@vock/*` **코드**를 import하지 않는다. 디자인 토큰 CSS만 가져온다 | `인터페이스계약-v2.md` §7 "landing은 독립(+디자인 토큰만 공유). 역방향·형제 간 직접 참조 = 빌드 실패". 코드를 공유하면 랜딩이 앱의 타입·런타임에 묶여 정적 사이트가 아니게 된다. `boundary-check.mjs`의 허용 맵에 `landing` 키를 넣고 자산 진입점(`.css`)만 허용한다 |
| L-3 | 가격을 적지 않는다. 유료에 관해 말할 수 있는 것은 "pro는 광고가 없다"뿐이다 | **v2 정본 가격이 존재하지 않는다.** `v1-승계원장/_index.md`가 v1의 ₩3,900을 "v1 최종이어도 v2 정본 아님 — 확장 제약 위 설계라 Phase C에서 재설계(사용자 확정)"로 표시했다. 정본 없는 숫자를 랜딩에 박으면 그것이 정본이 된다 |
| L-4 | 운영으로 바뀌는 수치를 **문구에 박지 않는다**. 한도가 있다는 사실은 적어도 된다 | `shared/src/types/limits.ts:1` "운영 한도 타입. 코드 기본값(DEFAULT_LIMITS)을 두되 어댑터가 env로 전부 덮어쓸 수 있다". SRS도 "구체 수치는 운영 설정으로 외부화"라고 적었다. 정적 HTML에 "주 7회"를 박으면 env를 바꾸는 순간 아무 신호 없이 거짓이 된다 |
| L-4b | 나중에 가격이나 한도를 **보여주게 되면 그때도 문구에 적지 않는다.** 운영 설정에서 빌드 시점에 주입한다 (사용자 결정 2026-07-30) | 사용자 원문: "고정값은 유연성 위반이니, 나중에 환경 변수로 셋업하는게 바람직함." 정본이 정해진 뒤에도 그 정본은 여전히 **운영이 바꾸는 값**이다. 두 번 적으면 정본이 둘이 되고, 랜딩 쪽이 낡는다. Astro는 빌드 시점에 env를 읽을 수 있으므로 문구에는 자리표시자만 두고 값은 빌드가 채운다. 이 규칙은 랜딩을 넘어 일반이다 — 운영이 바꾸는 값은 어디서도 손으로 적지 않는다 |
| L-5 | 카피는 `왜-배경지식-설득논거.md`의 근거강도 안에서만 쓴다. 그 문서의 금지선을 §5 검증에 그대로 옮긴다 | FR-954가 그 문서를 정본으로 지목했다. 그리고 그 문서 §0.5는 "위 표현은 초안 — 실제 카피 확정은 사용자 레드펜"이라고 스스로 적었다. **초안을 정본처럼 쓰면 근거 없는 주장이 제품의 공식 문구가 된다** — 이 프로젝트가 이미 한 번 겪은 형태다(AI가 쓴 코드 주석이 스펙으로 올라가 사용자 결정으로 되읽힌 일) |
| L-6 | 랜딩 언어는 ko 하나로 시작한다 | 앱의 문구는 **번역** 대상이지만 랜딩 카피는 **재작성** 대상이다(같은 주장을 언어마다 다르게 조립해야 한다). 카피가 확정되기 전에 4개 언어로 늘리면 레드펜 한 번에 네 벌을 고친다. 확정 후 늘린다 |
| L-7 | 랜딩은 `/`, 앱 SPA는 `/app`. 하나의 S3 버킷과 하나의 CloudFront 오리진을 공유한다 | ADR "랜딩·설득 콘텐츠(FR-954)만 Astro 정적 사이트로 분리해 같은 도메인 경로에 배치". 두 빌드가 모두 `dist/`를 뿜으므로 접두어를 갈라야 서로 덮어쓰지 않는다. 경로를 정하지 않으면 배포하는 사람이 그때그때 정하게 되고, 그것이 배포마다 달라진다 |
| L-8 | `.astro`를 세 게이트의 순회 대상에 넣는다(boundary·file-size·portability) | 세 스크립트의 필터가 `.ts`/`.tsx`/`.mjs`/`.css`뿐이라 `.astro`는 **무검사 구역**이 된다. 그 상태로 두면 §1-4가 요구한 "게이트로 강제한다"가 거짓이 된다 — 등록했다고 적혀 있고 실제로는 안 보는 것이 이 프로젝트에서 이미 나온 결함 모양이다 |
| L-9 | 랜딩에 앱 기능을 넣지 않는다. 앱으로 가는 진입 링크 하나만 둔다 | `인터페이스계약-v2.md` §1 "landing(Astro) — 정적. 설득 콘텐츠(FR-954). 앱 진입 링크만". 랜딩에서 입력을 받기 시작하면 그 순간 JS가 필요하고 L-1이 깨진다 |
| L-10 | 온보딩은 S6이 아니다 | FR-954가 "랜딩·온보딩"을 한 문장에 묶었지만 둘은 성격이 다르다. 온보딩은 앱 안에서 상태를 갖는 기능이고 랜딩은 상태 없는 정적 사이트다. 배포 경로도 다르다(L-7). 한 슬라이스에 묶으면 JS 0 제약이 온보딩 때문에 깨진다 |
| L-11 | 광고는 슬롯 자리만 두고 실집행·CMP는 하지 않는다 | 상위 스펙 §0 "광고 실집행(C5, 슬롯 자리만)". ADR-005가 랜딩을 AdSense 심사 대상으로 유도하고 TCF 2.2 CMP를 의무로 적었으나, 광고를 실행하지 않는 동안 CMP는 필요 없다. 심사 신청 시점에 함께 넣는다(§7 열린 항목) |

## 3. 계약

**의존 방향.** 루트 `README.md`의 의존 방향 문장에는 `landing`이 빠져 있다. 정본은 SoT다:

```
shared ← {core, persistence} ← http-app ← {aws, local}
shared ← ui-shared ← {web, desktop}
landing ← (없음).  ui-shared/styles.css 만 자산으로 가져온다
```

`boundary-check.mjs`의 허용 맵에 `landing: new Set()`을 넣고, CSS 진입점은 이미 있는 자산 예외
(`isAssetEntry`)로 통과시킨다. 키가 없으면 첫 import에서 게이트가 위반으로 판정한다.

**타입 검사.** 루트 `tsconfig.json` references에 넣지 않는다. `web`이 `composite: false`로 빠져 있고
`gate` 체인이 `tsc --noEmit -p packages/web/tsconfig.json`을 따로 두는 선례를 그대로 따른다.
그 줄을 복제하지 않으면 랜딩은 어떤 타입 검사도 받지 않는다.

**배포.** `DEPLOY.md`의 `- [ ] CloudFront + S3(웹/랜딩, C3 배포 시)` 항목에 L-7의 경로 분할을 적는다.

커밋에 남긴다.

## 6. 카피 작업 방식

1. `왜-배경지식-설득논거.md`의 9개 주장과 근거강도를 읽고, §0.5 프레임을 **출발점**으로 초안을 만든다.
2. §5의 금지선 표를 한 줄씩 대조한다.
3. 사용자 레드펜을 받는다. 그 문서가 스스로 "실제 카피 확정은 사용자 레드펜"이라고 적었으므로,
   레드펜 없는 카피는 확정이 아니다.
4. 확정된 뒤에만 다국어를 고려한다(L-6).

## 7. 열린 항목

- **가격과 무료 한도의 정본.** 지금 정하지 않는다(사용자 결정 2026-07-30). 정해질 때 L-4b에 따라
  운영 설정으로 두고 랜딩은 빌드 시점에 주입받는다. 즉 "가격이 정해지면 랜딩 문구를 고친다"가 아니라
  "가격이 정해지면 운영 설정에 넣는다"가 된다.
- **AdSense 심사와 CMP.** ADR-005가 랜딩을 심사 대상으로 유도하고 TCF 2.2 인증 CMP를 의무로 적었다.
  광고를 실행하는 슬라이스(C5)에서 함께 넣는다. 그때 CMP가 JS를 요구하므로 L-1을 그 페이지에 한해
  다시 판단해야 한다.
- **랜딩 다국어.** 카피 확정 후. 앱의 i18n 기계(`trIn`·`STRINGS`)를 랜딩에 쓸지, Astro의 i18n 라우팅을
  쓸지 미정 — L-2가 코드 공유를 금지하므로 앱 기계를 그대로 쓸 수는 없다.
- **온보딩(FR-954의 나머지 절반).** 앱 안 기능이므로 별도 슬라이스.
- **루트 `README.md`의 의존 방향 문장에 `landing`이 없다.** S6 커밋에서 SoT와 맞춘다.
- **`packages/scripts/README.md`가 이미 낡았다.** "경계 게이트 3중의 나머지 둘 = … dependency-cruiser
  (`pnpm cruise`)"라고 적혀 있으나 `cruise` 스크립트가 `package.json`에 없다. S6 커밋에서 함께 고친다.
