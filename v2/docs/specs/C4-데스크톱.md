## 0. 범위 / 비범위

- **포함**: `packages/desktop`(Tauri 셸) · `packages/adapters/tauri`(플랫폼 어댑터) · 데스크톱 인증
  경로 · 오프라인 캐시(FR-902) · 고유 기능 3종(FR-901·903·904) · 패키징·서명·업데이터(FR-905) ·

- **비범위**: 모바일(ADR-001이 경로만 확인) · OCR·음성(C-09 확정) · 새 화면·새 문구(D-1) ·

## 1. 이 사이클을 다른 사이클과 다르게 만드는 것

### 1-1. 화면은 이미 다 있다. 이번에 만드는 것은 **셸과 경계**다
`ADR-004`가 UI 공유를 P3로 못박았고(`ui-shared`에 화면, `web`·`desktop`은 얇은 셸 + 어댑터),
C3가 그 자리를 실제로 비워 뒀다. `web/src/deps.ts:1-3` 주석이 직접 그렇게 적고 있다:
> "데스크톱 셸(C4)은 App.tsx를 그대로 두고 이 파일만 자기 것으로 바꿔 끼운다 — 여정 배선이
> localStorage나 fetch를 알면 그 교체가 불가능해진다."

`TokenStore`(`ui-shared/src/api/token-store.ts:2`)와 `LocaleStore`(`i18n/locale.tsx:7`) 주석도
"데스크톱은 C4에서 자기 저장소"라고 미리 적어 뒀다. **즉 갈라 둔 자리가 맞았는지 이번에 검증된다.**
셸 교체만으로 앱이 뜨지 않으면 그것은 데스크톱 문제가 아니라 C3 분리가 덜 된 것이다.

### 1-2. 그러나 "웹 앱을 창에 담는다"가 아니다 — 오리진이 바뀐다
웹은 앱과 API가 **같은 오리진**이라서 성립하는 코드가 여럿이다. Tauri 웹뷰는 `tauri://localhost`
계열이라 그 전제가 전부 깨진다. 이것이 C4에서 가장 많이 부술 지점이고, 대부분 화면이 아니라
경계에 있다(§2 D-2·D-3·D-4).

### 1-3. FR-902는 "추가"가 아니라 **최초 구현**이다
계약 §156이 "클라(웹 IndexedDB/localStorage, 데스크톱 로컬 캐시)는 read-through 캐시"라고 적었지만,
**오늘 그런 캐시는 웹에도 없다** — 실측:
- `ui-shared/src/session/useSessionSync.ts:36` — `useRef(new Map<string, SessionRec>())` 인메모리
- `ui-shared/src/screens/terms/useDetail.ts:22` — `useReducer(step, { cache: {} })` 인메모리
- `web/src/App.tsx:144` — `useState<KeptMap>(emptyKept)` 인메모리
- localStorage에 있는 것은 **토큰과 로케일뿐**(`auth-storage.ts:9`, `locale-storage.ts:7`)

새로고침하면 전부 사라진다. 데스크톱이 만들 캐시가 이 프로젝트 최초의 영속 클라 캐시가 된다.
그래서 FR-902는 슬라이스 하나를 통째로 먹는다(§3 S3).

## 2. 동작 규칙

| # | 규칙 | 근거 |
|---|---|---|
| D-1 | 데스크톱은 **얇은 셸**이다. `App.tsx`·화면·문구를 고치지 않는다. 플랫폼 차이는 `deps.ts` 교체와 `adapters/tauri`로만 들어간다 | ADR-004 "P3 절충 패턴 … `web`·`desktop`은 얇은 셸 진입점 + 플랫폼 어댑터만". 화면을 고치기 시작하면 두 플랫폼의 화면이 갈라지고 FR-503(크로스 플랫폼 연속성)이 코드 차원에서 깨진다 |
| D-2 | **데스크톱은 클라이언트만의 일이 아니다. 서버도 바뀐다.** ① CORS ② `clientCheck`의 데스크톱 분기 ③ `users.locale` 배선 — 셋 다 C4 범위 | 실측: 서버 전 어댑터에 CORS 헤더 설정 **0건**(`grep -r "cors\|Access-Control" packages/adapters`). 웹이 되는 이유는 CloudFront 단일 오리진(ADR `:116`)이고, 다른 오리진이 생기는 순간 `fetch`가 브라우저 단에서 막힌다. `clientCheck`는 계약 `:164`·`C2.3-게이팅.md:7`이 "데스크톱=클라이언트 인증 토큰, 방식은 C4에서 확정"이라 지목했고 감사에서 **미구현**으로 확인됐다. `users.locale`은 `0001_init.sql:8`에 컬럼이 있으나 `UserRecord`(`shared/src/types/auth.ts:17`)에 필드가 없고 `toUser()`가 안 읽는다 — 데스크톱이 생기면 "웹에서 고른 언어가 데스크톱에 안 따라온다"로 바로 드러난다 |
| D-3 | API 주소는 **절대 URL**이고 빌드 시점에 주입한다. 상대경로를 쓰지 않는다 | `web/src/deps.ts:11` `import.meta.env.VITE_API_BASE ?? "/api"` — 폴백 `"/api"`가 같은 오리진 전제다. 데스크톱에서 이 폴백이 걸리면 웹뷰 자신을 가리켜 조용히 실패한다. **데스크톱 빌드에서는 폴백을 두지 않고 미설정이면 빌드를 깬다** — 조용한 오작동보다 시끄러운 실패가 낫다 |
| D-4 | 데스크톱 로그인은 **시스템 브라우저 + 루프백**이다. 웹의 OAuth 왕복을 재사용하지 않는다 | 계약 `:140` "데스크톱(Tauri): 시스템 브라우저 + 루프백/커스텀 스킴 콜백 — 구현은 adapters/tauri, 코어 계약은 동일(code+PKCE)". NFR-307이 v1 `launchWebAuthFlow` 승계를 금지했다. 실측으로 재사용 불가가 확인된 지점: `ui-shared/src/screens/auth/useAuth.ts:47,55,57,87`이 `location.search`·`history.replaceState`·`location.assign`으로 **같은 웹뷰 안 페이지 이동**을 전제하고, `:39`가 state·verifier를 `sessionStorage`에 둔다 — 콜백이 다른 프로세스(시스템 브라우저)로 오면 그 저장소가 이어지지 않는다. **서버 계약은 그대로다**: `platform: "web"\|"desktop"`이 이미 포트·서비스·프로바이더·라우트에 배선돼 있다(`auth-ports.ts:25`, `auth-service.ts:29`, `google-oauth.ts:44`, `auth-routes.ts:16`) |
| D-5 | 토큰은 localStorage에 두지 않는다. OS 보안 저장소를 쓴다 | `web/src/auth-storage.ts:4-5`가 스스로 "refresh 토큰이 localStorage에 있어 XSS에 노출된다"고 적어 둔 웹 전용 한계다. 데스크톱은 배포되는 바이너리라 같은 타협을 물려받을 이유가 없다. **단 `tauri-plugin-stronghold`는 v3에서 제거 예정**(ADR-001 리스크)이라 대체안 선정이 선행한다(§5 열린 항목) |
| D-6 | 오프라인은 **열람만**이다. 쓰기와 생성은 온라인 전용이고 정본은 항상 서버다 | 계약 `:156` "정본=서버. 클라는 read-through 캐시 + 오프라인 열람용. 쓰기는 online-only". FR-902 원문도 "생성 기능은 온라인 전용". 오프라인 쓰기를 허용하는 순간 충돌 해소 규칙이 필요해지고, 그것은 Q-07이 서버 정본으로 정리한 것을 되돌리는 일이다 |
| D-7 | **게이트를 코드보다 먼저 고친다.** 데스크톱을 안 보는 게이트 위에 코드를 쌓지 않는다 | 실측된 구멍 넷. ① 루트 `tsconfig.json` references와 `package.json:25` gate 체인 둘 다에 `desktop`·`tauri`가 없어 **타입 에러가 완전 침묵 통과**한다(web도 references엔 없고 별도 `--noEmit` 줄로 검사받는 선례가 있으므로 그 줄을 복제한다). ② `portability-guard.mjs`의 `PROMPT_ROOTS`에 `packages/desktop/src`가 없다. ③ `boundary-check.mjs`의 `ALLOWED`·`ASSET_ALLOWED`에 키가 없다 — `_shadow` 노트 2건이 이미 "desktop 패키지가 생기면"을 낡는 조건으로 예고해 뒀다. ④ **어떤 게이트도 `.rs`·`.toml`을 순회하지 않는다**(D-8 참조) |
| D-8 | **Rust 쪽에서 권한을 판정하지 않는다.** 티어·한도·게이팅은 서버만 판단한다 | NFR-308(크랙 방지) "유료 기능의 실체는 전부 서버에서 실행·검증 … 클라이언트를 변조·크랙해도 유료 기능이 열리지 않는 구조". 이 규칙이 특히 중요한 이유는 **강제할 게이트가 없기 때문**이다: `relation-index.py`가 이 코드베이스 유일의 "권한이 요청 입력에서 오는가" 자동 감시인데 파서가 `tree_sitter_typescript`·`tree_sitter_css`뿐이라(`:22-24`) Rust를 볼 수단 자체가 없다. **감시가 없으므로 규칙으로 못박고, 리뷰에서 사람이 본다** — 없는 게이트를 있는 것처럼 적지 않는다 |
| D-9 | Linux 빌드는 Linux에서 한다. Windows에서 크로스 컴파일하지 않는다 | ADR-001 "glibc 함정: 오래된 베이스 이미지(Ubuntu 22.04 등)에서 빌드할 것". C4의 실빌드 범위는 **Windows 우선**이고, Linux는 빌드 호스트가 생긴 뒤다 — 사용자의 2단계 인프라 목표(리눅스 서버 직접 운영)가 그 호스트를 겸할 수 있다 |
| D-10 | 폰트를 번들에 내장한다 | NFR-502 "데스크톱 앱은 폰트를 번들에 내장해 오프라인에서도 동일하게 렌더링되어야 한다". 현재 웹·랜딩은 Pretendard를 jsDelivr CDN에서 받는다 — 오프라인 열람(FR-902)을 켜 놓고 폰트만 네트워크에 의존하면 그 화면은 오프라인에서 다른 모양이 된다 |
| D-11 | 전역 단축키·알림은 **선택 기능**이고, 안 되는 환경에서 우아하게 강등한다 | FR-903·904 원문이 "제공할 수 있다"(FR-901·902·905는 "해야 한다"). ADR-001 "Wayland 전역 단축키는 셸 무관 공통 제약 … Linux에서 우아한 강등 설계 필요". 못 하는 것을 숨기지 말고 설정 화면에서 "이 환경에서는 불가"로 보이게 한다 |
| D-12 | **웹과 데스크톱의 기획은 한 선에서 움직인다.** 여정·화면·문구를 바꾸는 결정은 플랫폼을 지목하지 않는다 — `ui-shared`에 한 번 일어나 두 플랫폼에 같이 흐른다. 데스크톱 고유 기능(FR-901~904)은 여정의 **분기**가 아니라 **능력(capability)의 추가**로 모델링한다: 화면은 하나이고, 그 화면이 주입받은 능력의 유무에 따라 그 자리를 보이거나 감춘다. 공유 가능한 로직(캐시 조율 등)은 데스크톱 전용 코드가 아니라 `ui-shared` 포트로 두고, 플랫폼은 구현만 갈아 끼운다 (사용자 지시 2026-07-30) | 사용자 원문: "가장 중요한건 웹페이지와 데스크톱 앱의 기획은 동일선상에서 수정되어야 해. 비례 관계니까." 문서 뿌리는 이미 있다 — SRS `:54` "데스크톱 프로그램: 웹과 같은 기능에 더해 데스크톱 고유 기능을 추가한다", FR-503(어느 플랫폼에서 로그인해도 같은 자산·진행 상태), ADR-004 P3(화면은 `ui-shared` 한 벌). D-1이 코드 방향("데스크톱이 화면을 안 고친다")을 막고, D-12는 **기획 방향**을 막는다: 이후 어떤 사이클이든 여정을 바꾸는 스펙은 두 플랫폼에 동시에 적용되는 문장으로 쓰고, 한쪽에만 적용되는 여정 변경은 그 자체로 스펙 결함으로 본다. 갈라진 두 기획은 코드 게이트로 못 잡는다 — 그래서 규칙이 스펙 층에 있어야 한다 |

## 3. 슬라이스 계획

패키징 형식이 자동 업데이트·서명·샌드박스 권한을 좌우하는 **선결 변수**라고 SRS `:263`이 못박았으므로,
형식 결정은 S1에서 하고 실집행은 S5로 미룬다.

| # | 슬라이스 | 내용 | 이 슬라이스가 끝나면 볼 수 있는 것 |
|---|---|---|---|
| S1 | 셸 기동 | `packages/desktop` + `adapters/tauri` 신설, 같은 SPA 로드, `deps.ts` 교체(절대 URL), **게이트 4종 등록(D-7)**, 패키징 형식 결정 | 데스크톱 창에서 앱이 뜬다(로그인 전 화면까지) |
| S2 | 인증과 경계 | 시스템 브라우저+루프백 콜백, OS 보안 저장소, **서버 CORS + `clientCheck` 데스크톱 분기 + `users.locale` 배선**(D-2) | 데스크톱에서 로그인하고 웹과 같은 자산이 보인다 |
| S3 | 오프라인 캐시 | FR-902 최초 구현. read-through, 열람 전용, 정본=서버. **조율 로직은 `ui-shared` 포트, 데스크톱은 저장소 구현만**(D-12) — 웹이 나중에 IndexedDB로 같은 자리를 채울 수 있는 모양 | 네트워크를 끊어도 저장된 세션·어휘를 연다 |
| S4 | 고유 기능 | FR-901 파일 첨부, FR-904 알림, FR-903 전역 단축키(강등 포함). **화면 분기 금지 — 어댑터가 능력을 선언하고 화면은 하나**(D-12) | 파일을 끌어다 놓고, 알림이 오고, 단축키로 창이 뜬다 |
| S5 | 패키징·서명·업데이터 | Windows 설치 파일, 코드 서명, FR-905 업데이터 | 설치 파일이 나오고, 업데이트가 서명 검증을 거쳐 적용된다 |

각 슬라이스는 이 프로젝트 패턴대로 **스펙 → 검토 → 구현 → 커밋**이고, 화면이 바뀌는 슬라이스는
사용자 시각 확인을 거친다.

## 4. 완료 기준

- Windows에서 설치 파일이 나오고, 설치한 앱이 로그인·좁히기·어휘 생성·담기까지 웹과 같은 결과를 낸다.
- 네트워크를 끊은 상태에서 저장된 세션·어휘를 열람할 수 있고, 생성 시도는 명확히 거절된다.
- 게이트 4종이 데스크톱을 실제로 본다 — 등록했다는 말이 아니라, 일부러 어긴 코드를 넣어 **실패하는 것을 확인**한다.
- 서명 없는 업데이터가 켜져 있지 않다(NFR-604와 FR-905는 쌍으로만 유효).

## 5. 열린 항목

- **코드 서명 인증서.** Windows OV 연 $200~300(ADR-001). **지출 결정은 사용자 몫**이고, 정해지기
  전까지 S5의 서명·업데이터는 착수하지 않는다. 서명 없이 업데이터만 켜는 선택지는 없다.
