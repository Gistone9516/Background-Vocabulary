# C3 S4 스펙 — 담기와 게이팅 UX (SoT §1·§3·§4에서 파생)

> 상위 = [C3-웹랜딩.md](C3-웹랜딩.md). 앞 = [C3-S3b](C3-S3b-카드상세.md).
> v1 코드는 **동작 명세로만** 쓴다. 구조는 계승하지 않는다(코드규약 §6~§9).

## 0. 범위

- **포함**: 담기 토글 · kept(담은 어휘) 화면 · 기본 정리(무비용 클라 템플릿) · 그룹별 추가 생성 · paywall 화면 · 티어 배지와 헤더 재판단.
- **제외**: `POST /summarize`(AI로 더 정리) → **S4b**(아래 §0-2) · 담기 서버 저장 → S5 · 실 결제 → C5.

### 0-1. 이월

- **"AI로 더 정리"(`/summarize`) → S4b.** SoT §3-1은 출력을 `PrimerDoc`으로 정하고 있으나 코드의 `Prompt4Out`은 v1 형태다. 이 개편은 C5 이월 항목(`C2.1-영속계층.md:11`)이므로 서버 계약을 먼저 맞춘 뒤 클라를 붙인다. 무비용 **기본 정리**는 클라 템플릿이라 S4에 포함한다.
- **담기 서버 저장 → S5.** 서버 CRUD는 전부 Bearer 필수이고 로그인 UI는 S5a에서 만든다. S4는 담기를 화면 상태로만 유지한다.

## 1. v1에서 계승하는 동작

| # | 규칙 | 근거 |
|---|---|---|
| K-1 | 카드마다 담기 토글이 있고 담긴 것은 표시가 바뀐다 | v1 `keep_on`/`keep_off` |
| K-2 | 같은 어휘를 두 번 담을 수 없다. 정규화 키로 판정한다 | `AssetTerm.term_norm` 주석 "중복 담기 방지" |
| K-3 | 담기로는 세션을 완료 처리하지 않는다. 완료 전이는 생성 `done`에서만 | v1 주석 "담기로는 narrow를 지우지 않는다" |
| K-4 | 담은 어휘 화면에서 목록을 보고 되돌아갈 수 있다 | v1 `kept_back_terms`, `kept_back_home` |
| K-5 | 기본 정리는 서버를 부르지 않는다. 담은 어휘로 즉시 만든다 | SoT §1 "무비용·즉시" |
| K-6 | 그룹별 추가 생성은 그 그룹만 이어붙인다. 누적 상한을 함께 지킨다 | `groupGen`, `maxTotal` |
| K-7 | pro 전용 기능을 무료가 누르면 페이월로 끌고 가지 않고 그 자리서 알린다 | v1 `proNotice` 주석 |

## 2. v1 구조에서 바꾸는 것

| v1 | 문제 | v2 |
|---|---|---|
| `terms[].kept` 불리언을 카드 배열 안에 섞음 | 카드는 서버가 준 값인데 사용자 상태가 끼어들어 원본이 오염된다 | 담긴 키 집합을 따로 둔다. 카드는 서버 값 그대로 |
| 담은 어휘 수를 여러 곳에서 셈 | 카운터 중복 | 집합 크기 하나에서 파생 |
| pro 판정을 화면마다 검사 | 조건이 흩어짐 | 티어는 앱 수준 하나. 화면은 `locked` 여부만 받는다 |

## 3. 계약

```ts
// 담긴 어휘. 카드 원본을 건드리지 않고 키 집합으로만 관리한다.
export type KeptSet = ReadonlyMap<string, Term>;   // key = term_norm

export function normTerm(term: string): string;    // 중복 판정 키(K-2)

export type KeepEvent =
  | { t: "toggle"; term: Term }
  | { t: "clear" };
```

기본 정리(K-5)는 순수 함수다.

```ts
export function buildBasicPrimer(args: {
  area: string; topic: string; condition: string; kept: Term[];
}): string;    // 복사해 붙일 한 덩어리
```

## 4. 검증

`e2e-keep.mjs`를 게이트에 추가한다.

| 케이스 | 기대 |
|---|---|
| 담기 토글 | 집합에 추가, 다시 누르면 제거 |
| 같은 어휘 다른 표기 | 정규화 키가 같으면 중복 담기 안 됨(K-2) |
| 담기 후 카드 원본 | `Term` 객체가 변형되지 않음 |
| 기본 정리 | 담은 어휘 0개면 빈 결과가 아니라 안내, 1개 이상이면 전부 포함(K-5) |
| 그룹 추가 생성 | 누적 상한을 넘지 않음(K-6) |

## 5. 함께 처리하는 것

- **헤더 재판단(S1부터 유예).** 티어 배지가 헤더에 들어오므로 64em 이상에서 헤더를 통째로 숨기던 규칙을 걷고, 사이드바와 중복되는 브랜드만 숨긴다.
- kept·paywall 구간 `tokens.css`를 rem으로 옮긴다.
- 문구는 v1 원문을 확인하고 그대로 쓴다.

## 6. 열린 항목

- 로그인 UI의 소속 슬라이스(§0-1 ②). S5에 넣는 것이 자연스럽지만 사용자 확정이 필요하다.
- `/summarize` 출력 계약 정합(§0-1 ①). S4b 착수 전 서버부터 맞춘다.
