## 0. 범위

**포함.** 진입 화면 하단 2트랙 구조 신설 · 재방문 능동 카드(FR-707) · 복사 뒤 종료 확인(FR-608) · 담기 상태 서버 복원 · 마인드맵과 가변 두 슬롯의 자리 신설.

**제외.** 마인드맵 본체(S4가 능력을 꽂는다) · 가변 슬롯에 들어갈 내용물(스코프별 주입은 배선만 하고 내용은 이후 슬라이스) · `domain_tags` 생산자(별도) · 간격반복·복습 신호(d-3, 아래 V-21) · 광고 카드.

## 1. 왜 이 기능이 필요한가

v1 비판검토의 진단이 근거다. 단발 세션의 완결성은 높은데 **세션 이후가 비어 있다.** 담은 어휘를 메인 AI에 붙여넣고 나면 돌아올 이유가 구조적으로 없다.

그런데 v2에서 상황이 v1보다 나빠졌다. v1은 히스토리가 진입 화면 하단에 목록으로 있었지만, v2는 그것이 **사이드바 드로어 안으로 들어갔다.** 목록을 보려면 드로어를 열어야 한다.

이 제품의 핵심 원리는 재인이 회상보다 낫다는 것이고, 세션 안에서는 전부 클릭으로 처리한다. **재방문 동선에서만 자기 원칙을 위반하고 있다.** 능동 카드는 돌아올 이유를 회상시키지 않고 재인시킨다.

## 2. 화면 구조

칩 아래에 트랙 격자를 신설한다. 지금 그 자리에는 아무것도 없다.

```
제목 · 부제                       .heroHead (고정 높이)
─────────────────────────────
입력창 (+조건부 요소들)             .composer …
예시 칩                            .suggest
─────────────────────────────    ← 여기부터 신설
넓은 화면                          좁은 화면
┌────────────┬────────────┐      ┌────────────┐
│ 이어서하기   │            │      │ 이어서하기   │
├────────────┤   가변 슬롯  │      ├────────────┤
│ 마인드맵    │            │      │  가변 슬롯   │
│ (S3는 빈다) │            │      ├────────────┤
└────────────┴────────────┘      │  마인드맵    │
                                 └────────────┘
```

**DOM은 하나이고 순서는 카드 → 가변 → 마인드맵이다.** 좁은 화면의 시각 순서와 일치하고, 넓은 화면에서는 격자가 재배치한다.

### 3-3. 카드의 데이터

| # | 규칙 | 근거 |
|---|---|---|
| V-15 | 카드가 가리키는 세션이 세션 목록의 첫 항목과 다르면 **카드를 띄우지 않는다** | SoT §3-3의 정본 분리 조항. 틀린 카드보다 없는 카드가 낫고, 다음 새로고침에서 자연히 맞는다 |
| V-16 | 목록 응답이 카드를 덮지 않는다 | 서버 수리 원칙이 "나중 응답이 캐시를 덮는다"이므로 예외를 적지 않으면 원칙대로 처리되고, 목록은 담은 개수를 모르므로 그 값이 사라진다 |
| V-17 | 카드 재조회는 **`journey.at`이 진입으로 전이할 때 · 선택된 프로젝트가 바뀔 때 · 로그인 상태가 바뀔 때** 셋에만 의존한다 | 기존 `useSessionSync`는 의존값이 바뀔 때만 조회하고 홈 복귀 경로에 재조회 호출이 없다. 그 관례를 답습하면 카드는 앱 실행 중 한 번만 로드되는 정적 스냅샷이 된다. **v1이 같은 자리에서 실제로 겪은 사고다** — 홈 복귀 시 다시 부르지 않아 카드가 사라졌고, 복귀 시 명시적으로 다시 부르는 것으로 고쳤다 |
| V-18 | 담은 개수 조회와 세션 재개 시 담기 복원은 **같은 레포지토리 메서드 하나**를 쓴다 | `AssetRepository`에 세션 스코프 목록이 없어 어느 쪽을 하든 신설이 필요하다. 세션당 담기 상한이 무료 8·유료 32라 목록을 읽어 길이를 세도 부담이 없다 |
| V-19 | 세션 재개 시 담기 상태를 서버에서 채운다. 그리고 프라이머가 읽는 네 값(주제·조건·분야·작업유형)은 **좁히기 맥락과 재개된 기록 둘 중 살아 있는 쪽에서 한 곳으로 모아** 읽는다 | **[2026-08-18 개정 — 구현 중 정정]** 원문은 "`lastCtx`도 함께 채운다"였으나 **채울 수 없다.** `NarrowCtx`는 `classifyOut`과 `firstQuestion`을 요구하고 둘 다 `rec.narrow` 안에 있는데, 생성이 끝난 세션은 `narrow`가 `null`이다. 기존 재개 경로가 `lastCtx`를 안 채운 것은 누락이 아니라 불가능이었다. 네 값 자체는 `SessionRec` 최상위(`topic`·`user_condition`·`area`·`job_type`)에 있으므로, 읽는 쪽을 한 함수로 모으고 그 함수가 두 출처 중 살아 있는 쪽을 고른다. 값이 두 벌이 되는 것이 아니라 **생산자가 둘이고 소비자가 하나**다 |
| | **이 규칙이 없으면 무엇이 보이는가** | 재개한 세션에서 담은 어휘 화면을 거쳐 종착 화면으로 가면 분야와 조건이 빈 채로 프라이머가 조립된다. 이 경로는 담기 복원 전에는 도달 불가였다(담은 개수가 0이라 링크가 안 떴다) — 이 슬라이스가 길을 여는 순간 드러나는 결함이라 같은 슬라이스에서 닫는다 |
| V-20 | 오프라인이면 카드를 띄우지 않는다 | 오프라인 캐시는 세션 목록 첫 페이지만 감싼다. 신설 조회는 그 캐시에 없으므로 실패하고, 개수 없는 카드는 재인 단서가 약해 존재 이유가 흐려진다 |

## 4. 계약 변경

**이미 커밋된 것**(`d9fe383`) — `ResumeCard` 타입, `GET /sessions/recent`, 정본 분리 조항.
