# C4 S3 스펙 — 오프라인 캐시 (FR-902 최초 구현) + 폰트 내장 (D-10)

> 상위 = [C4-데스크톱.md](C4-데스크톱.md) (D-6·D-10·D-12). 계약 §3-3 동기화 규칙(:156)이 지배한다.
> 규칙: DS3-1~DS3-8 (8건)

## 0. 범위 / 비범위

- **포함**: 오프라인 read-through 캐시(세션 목록·세션 레코드) · 오프라인 고지 UI · 데스크톱
  폰트 내장 · **폰트 미적용 결함 수정**(실측 발견 — 웹 포함).
- **비범위**: 오프라인 쓰기 큐(계약이 명시적으로 범위 밖) · 상세(Prompt5Out) 캐시(어휘 상세는
  세션 레코드의 generated에 이미 있고, 추가 상세는 온라인 생성물) · 웹 IndexedDB 구현(자리만 —
  `offline: null`).

## 1. 핵심 설계 결정

### 1-1. 조율은 ApiPort 데코레이터다 — 훅을 고치지 않는다
`withOfflineCache(api, store, onChange): ApiPort`가 **읽기 두 경로만** 감싼다:
`listSessions`(성공 → 캐시 덮어쓰기 / network 실패 → 캐시 폴백)와 `getSession`(동일).
나머지 메서드는 그대로 통과한다 — **쓰기를 안 감싸는 것만으로 D-6(오프라인은 열람만)이
구조로 성립한다.** 오프라인에서 저장·담기·삭제는 지금과 똑같이 실패하고 삼켜진다(S-3).

이 모양을 고른 이유 둘: ① `useSessionSync`는 손대지 않는다 — 훅은 자기가 캐시를 쓰는지도
모른다(폴백된 목록은 `cursor: null`이라 "더 보기"도 자연히 사라진다). ② 노드에서 목 ApiPort로
검증 가능하다(e2e-auth-client가 HttpApiClient를 검증하는 집 선례 그대로).

### 1-2. `off`를 재활용하지 않는다 — 오프라인은 셋째 축이다
실측: `off`는 비로그인(S-1 "사이드바가 알린다")의 신호고, 네트워크 실패는 현재
`off:false, items:[]`로 떨어져 **빈 목록과 구분 불가**다. 오프라인은 데코레이터의 `onChange`
콜백 → journey 상태 → 사이드바 고지 한 줄로 흐른다. `SessionListState`는 형태 그대로다.

### 1-3. 서버 수리 원칙, 그리고 로그아웃 = 캐시 삭제
계약 §3-3: "클라는 서버 응답으로 자기 캐시를 덮는다." 성공 응답은 **항상** 캐시를 덮고,
캐시 우선(stale-while-revalidate류)은 계약 위반이라 만들지 않는다. 로그아웃하면 캐시를
지운다 — 다음 사람이 같은 기기에서 로그인했을 때 남의 목록이 보이는 것은 소유권 규칙
(PUT 409 횡령 방지)의 클라이언트 판 위반이다.

### 1-4. 폰트: 내장하기 전에, 켜지지 않던 것을 먼저 켠다 (실측 결함)
CDN CSS는 `'Pretendard Variable'`을 선언하는데 참조하는 곳이 0곳이라 **웹폰트가 로드조차
안 되고 있었다**(`document.fonts.check` = 미로드, 5185 실측). `tokens.css:9`의 `'Pretendard'`는
시스템 폴백으로만 그려져 왔다 — v1에서 계승된 잠복 결함. 수정은 한 줄이고 두 플랫폼이 같이
바뀐다(D-12): `tokens.css` 스택 선두에 `'Pretendard Variable'` 추가. 데스크톱은 vendored
woff2(가변, weight 45~920)를 같은 이름으로 `@font-face` 선언하고 CDN 링크를 지운다(D-10).
Pretendard는 SIL OFL이라 동봉이 합법이고 LICENSE.txt를 폰트 옆에 둔다.

## 2. 동작 규칙

|---|---|---|
| DS3-1 | 오프라인 신호는 `off`와 다른 축이다. 캐시 폴백이 일어나면 사이드바에 고지 한 줄, 회복(성공 응답)하면 사라진다 | S-1(off=비로그인)을 흔들면 안 된다. 실측: 현재 네트워크 실패는 빈 목록과 구분 불가 |
| DS3-2 | 데코레이터는 `listSessions`·`getSession`만 감싼다. 쓰기 메서드는 통과 | §1-1. D-6이 검사가 아니라 구조로 성립한다 |

| DS3-8 | 캐시 쓰기는 명시 `save()`다. autoSave에 맡기지 않는다 | plugin-store 기본은 "정상 종료 시 저장"(공식 문서). 비정상 종료로 캐시가 날아가면 오프라인 열람이 조용히 비는 것이 이 슬라이스에서 가장 억울한 실패 모양이다 |

## 4. 검증

**실측 결과(2026-07-30)**: e2e-offline 15/15(아래 표 전항 + 검색·커서 결과가 캐시를 안 덮는 것,
삭제 성공 시 캐시 동반 삭제). 폰트 = 5185에서 `Pretendard Variable/loaded` + CDN 요청 0.
창 재빌드(plugin-store 포함) 기동 캡처. 게이트 256 PASS. journey.tsx가 302행으로 상한을 넘어
**shell-bridge.ts로 분리**했다(능력 배선과 화면 전환은 다른 책임 — 예외 등록이 아니라 분리가 맞았다).

**정직한 한계**: 창 안에서 "로그인 → 목록 캐시 → 네트워크 차단 → 열람"의 전체 실측은 데스크톱
로그인(Google 콘솔 등록, 사용자 킵 항목)에 걸려 있다. S3의 기계 검증은 데코레이터 e2e와 폰트
실측까지고, 창 오프라인 실측은 콘솔 등록 후 S2 마감과 함께 한 번에 한다.

## 5. 열린 항목

- **웹 IndexedDB 구현.** 포트는 준비됐고 `offline: null`로 강등돼 있다. 웹에 넣을 시점은 별도 결정.
- **어휘 자산 목록(listAssets) 캐시.** FR-902의 "어휘 자산"은 세션 레코드(generated) 열람으로
  1차 충족된다. 프로젝트 자산 목록까지 캐시할지는 S4에서 화면 수요를 보고 정한다.
