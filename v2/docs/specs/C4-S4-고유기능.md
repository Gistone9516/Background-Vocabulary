# C4 S4 스펙 — 고유 기능: 파일 첨부(FR-901)·퀵 캡처(FR-903), 그리고 알림(FR-904)의 이월

> 상위 = [C4-데스크톱.md](C4-데스크톱.md) (D-8·D-11·D-12). TR-06(티어 배치는 참고 기본값)이 게이팅을 지배한다.
> 규칙: DS4-1~DS4-8 (8건)

## 0. 범위 / 비범위

- **포함**: 파일 첨부 end-to-end(진입 UI → classify/next/recommend → 세션 보존·재개) · 서버 측
  context 하드닝(절단 + env 주도 티어 게이트 — **브리핑 발견: 지금은 서버가 아무것도 안 본다**) ·
  전역 단축키 퀵 캡처(강등 포함).
- **비범위·이월**: **FR-904 복습 알림** — 알릴 대상(복습 개념)이 v2에 없다(실측: FR-502의 인앱
  정렬 한 줄과 백로그 09-34뿐, 코드 0건). "제공할 수 있다"인 선택 기능이므로 껍데기 알림을 만들지
  않고 **복습 기능이 생기는 슬라이스에 붙인다**. 파일 바이트 상한(MB) — 정본 없음, 문자 수 상한만
  존재. listAssets 캐시(S3 이월 항목) — 이번에도 화면 수요 없음, 보류.

## 1. 핵심 설계 결정

### 1-1. 첨부는 데스크톱 기능이 아니라 **두 플랫폼이 같이 켜지는 기능**이다 (D-12)
v1 첨부는 웹 표준(File·FileReader)만 썼고, v2 통로(Prompt*In.context_object → DB → LLM 프롬프트)는
이미 전부 배선돼 있다 — 없는 것은 UI 생성 지점 하나뿐(실측). 데스크톱 웹뷰도 같은 웹 표준을 쓰므로
**어댑터 코드 없이 화면 한 벌로 두 플랫폼이 동시에 켜진다.** 유일한 데스크톱 차이는 Tauri가
드롭 이벤트를 가로채는 것이고, `dragDropEnabled: false`로 소거한다 — 공식 스키마 원문:
"Disabling it is required to use HTML5 drag and drop on the frontend on Windows."
FR-901의 "웹보다 넓은 형식"은 지금 양쪽 다 텍스트 계열(C-09가 OCR·자동읽기를 금지하므로 바이너리
추출은 애초에 범위 밖)이라 차이가 없다 — 차이가 생기는 날 능력 필드를 만든다.

### 1-2. 티어 게이트는 env 주도다 — v1 기본값을 계승하되 박지 않는다 (TR-06)
"파일 첨부=pro"는 **참고 기본값**이고 정본은 C5 결제 재설계다. 서버 코드에 pro를 하드코딩하면
C5가 뒤집을 값을 박는 것이고, 클라만 잠그면 API 직접 호출로 뚫린다(NFR-308). 그래서:
`Limits.attachRequiresPro`(기본 true = v1 참고값, **어댑터가 env로 덮는 기존 관례** 그대로) →
서버 게이팅이 free+context_object를 402로 거부, `/config`가 같은 값을 클라에 실어 UI가 잠금을
그린다. 값은 한 곳(limits)에서 나와 서버 판정과 화면 표시가 갈라질 수 없다.

### 1-3. 서버 절단 — 선언만 있고 강제가 없던 하드닝
`maxContextChars` 주석은 "보안 하드닝, anti-abuse"라 선언하는데 강제 지점이 0곳이다(실측 — 클라
절단은 v1에도 있었지만 그건 UX지 하드닝이 아니다). 라우트가 파이프라인에 넘기기 전에 절단한다.
거부가 아니라 절단인 이유: 클라가 정직하게 잘라 보낸 것과 같은 결과가 되어야 정직한 클라와
악의적 클라의 출력이 같아진다.

### 1-4. 퀵 캡처 = 창 호출까지다. 여정을 건드리지 않는다
FR-903 원문은 "빠른 입력창을 **호출**". 단축키는 창을 show·unminimize·focus까지만 한다 —
좁히기 중간에 진입 화면으로 끌고 가면 진행을 잃는다. 등록 실패(다른 앱 선점, Wayland)는
경고 1줄로 강등하고 앱은 그대로 돈다(D-11 — ADR 실측: Wayland는 프로토콜 차원 미지원).

## 2. 동작 규칙

| # | 규칙 | 근거 |
|---|---|---|
| DS4-1 | 첨부 판정·읽기는 v1 `file.ts` 이식(텍스트 계열만, FileReader). 바이너리는 `attach_texterr`로 거절 | C-09(OCR·자동읽기 금지)와 정합. v1이 검증한 코드 |
| DS4-2 | 클라 절단 = `/config`의 `maxContextChars`(잘리면 `attach_truncated` 고지). **서버도 같은 값으로 절단한다**(§1-3) — 클라 값은 UX, 서버 값이 하드닝이다 | 실측: 서버 강제 0곳. 수치는 양쪽 다 limits 한 곳에서 온다 |
| DS4-3 | 티어 게이트: `attachRequiresPro`(env 주도, 기본 true) — 서버는 free+context를 402 `PRO_ONLY`로, UI는 같은 플래그로 자물쇠(`.attach.locked`, v1 CSS 계승)를 그린다. **free에게도 버튼은 보인다** | TR-06(참고 기본값)·NFR-308(서버 강제)·L-4b(env). v1 감사 지적 c-1-3(안 보이다가 페이월로 튀는 다크패턴) 반영 — 잠긴 것이 보이는 게 낫다 |
| DS4-4 | context는 NarrowCtx에 실려 classify·next·recommend 세 곳에 나가고, 세션에 저장·재개된다. SessionRec **형태 불변**(필드는 이미 있다) | v1 선례(3곳 반복 전송). 재개 후 첨부 맥락이 사라지면 이어하기가 다른 탐색이 된다 |
| DS4-5 | `dragDropEnabled: false` — 데스크톱 드롭도 HTML5 경로 하나다 | §1-1. 경로가 둘이면 한쪽만 고치는 수정이 생긴다 |
| DS4-6 | 퀵 캡처 단축키 = `CommandOrControl+Shift+K` 고정. 등록 실패 = 경고 1줄 강등, 커스터마이즈는 설정 화면이 생길 때 | D-11. 설정 화면이 없는데 설정값을 만들면 저장할 곳부터 지어야 한다 |
| DS4-7 | 전역 단축키 권한은 명시 3종(`allow-register/unregister/is-registered`) + 창 조작 3종만 | 플러그인 기본값이 전부 거부라(공식 문서) 명시가 강제다. 필요한 것만 연다 |
| DS4-8 | 새 문구는 v1 키 이름 그대로(`attach`·`attach_short`·`attach_remove`·`attach_texterr`·`attach_truncated`·`attach_pro_note`) — v1 4로케일 원문이 있으므로 port-i18n의 v1 이식 경로를 탄다. AI 작성이 아니다 | S-37 출처 추적. v1 원문이 있는데 새로 지으면 이식분과 창작분의 구분이 무너진다 |

## 5. 열린 항목

- **FR-904 복습 알림** — 복습 기능(FR-502 계열)이 생기는 슬라이스로 이월(§0). 그때 notification
  플러그인·설정 끄기(설정 화면 전제)와 함께.
- **티어 배치 정본** — C5 결제 재설계가 `attachRequiresPro`의 최종값을 정한다(TR-06). env라 코드
  변경 없이 뒤집힌다.
- **퀵 캡처 단축키 커스터마이즈** — 설정 화면이 생길 때.
- **"웹보다 넓은 형식"** — PDF 등 텍스트 추출이 필요한 형식을 데스크톱에 더하는 날, 그때 능력
  필드(ShellDeps)를 만든다. C-09(OCR 금지)와의 경계를 그 스펙에서 그을 것.
