# C4 S2 스펙 — 인증과 경계 (데스크톱 로그인 + 서버가 바뀌는 세 가지)

> 상위 = [C4-데스크톱.md](C4-데스크톱.md) (D-2·D-4·D-5·D-8·D-12).

## 0. 범위 / 비범위

- **포함**: 서버 CORS(env 주도) · clientCheck(웹 Origin/데스크톱 토큰, **남용 억제**) · `users.locale`
  배선(FR-952) · `googleClientId` 부트 배선(브리핑 발견 — 어느 부트도 안 채우고 있었다) ·
  데스크톱 OAuth(시스템 브라우저 + 루프백) · OS 보안 저장소 토큰 · `adapters/tauri` 신설.
- **비범위**: 실 Google 콘솔 등록(사용자 핸즈온 — 계약 §9 "F6 실측으로 확정") · 오프라인 캐시(S3) ·
  refresh 토큰 저장 위치 재검토(S5a §6이 "S5 본편"으로 지정한 항목).

## 1. 핵심 설계 결정

### 1-1. ShellAuth를 넓힌다 — 여정에 플랫폼 분기를 넣지 않는다
`journey.tsx`의 그림자 노트가 낡는 조건으로 미리 적어 둔 그대로다: "redirectUri 외의 것이
필요해지면 이 파일이 아니라 **포트를 넓힐 것**". 웹의 OAuth 왕복(페이지 이동 + 마운트 콜백)과
데스크톱의 왕복(같은 페이지 유지 + 루프백 대기)은 **이동 방식**이 다를 뿐 PKCE·교환·상태 관리는
같다. 그래서 다른 부분만 포트로 뺀다:

```ts
export interface ShellAuth {
  platform: "web" | "desktop";
  redirectUri(): string | Promise<string>;   // 데스크톱: 리스너를 시작한 뒤에야 포트를 안다
  navigate(url: string): void | Promise<void>; // 웹: location.assign / 데스크톱: 시스템 브라우저
  waitForCallback?(): Promise<string>;       // 데스크톱만: 루프백이 받은 콜백 URL. 웹은 마운트 경로
}
```

`useAuth`는 `waitForCallback`이 있으면 그 자리에서(페이지 이동 없이) 콜백을 처리하고, 없으면
지금의 마운트 경로를 탄다. 화면(AuthButton)은 한 벌 그대로다(D-12).

### 1-2. 보안 저장소 = Rust `keyring` 크레이트 직접. 커뮤니티 래퍼를 쓰지 않는다
웹 조사 결과(§6): stronghold는 v3 제거 예정(공식 문서 명시), 생태계 방향은 OS 자격 증명
저장소(keyring)다. 커뮤니티 플러그인 `tauri-plugin-keyring`은 스타 20·커밋 12로 어리다.
**의존은 래퍼가 아니라 기반에 둔다** — `keyring` 크레이트(사실상 표준, Windows Credential
Manager / Linux Secret Service)를 src-tauri의 커맨드 3개로 감싼다.

**D-8과의 관계를 명시한다**: D-8이 금지하는 것은 Rust에서의 **권한 판정**(티어·한도·게이팅)이다.
`secret_get/set/delete`는 판정이 없는 배관이고, 판정 근거(토큰)는 언제나 서버가 검증한다.
S1의 "커스텀 커맨드 0"은 이 슬라이스에서 "판정 커맨드 0"으로 바뀐다 — 커맨드 목록과 각각이
배관인 이유를 `lib.rs` 주석에 적는다.

### 1-3. TokenStore 포트는 동기로 유지한다
키링 호출은 비동기지만 `TokenStore.read()`는 동기다. 포트를 async로 바꾸면 `http-client`의
매 요청 경로와 웹 구현이 전부 바뀐다 — 포트 하나 지키자고 전 계층을 흔드는 쪽이 더 위험하다.
대신 **시작 시 1회 로드 + write-through**: 앱 기동 때 키링에서 읽어 메모리에 두고, write/clear는
메모리 즉시 + 키링 반영은 뒤에서 한다. 실패해도 메모리 상태가 화면과 일치하므로 UX는 안 깨지고,
다음 기동에서 로그인이 풀려 있는 것으로 드러난다(조용한 거짓 로그인보다 낫다).

### 1-4. locale 정본 = 서버 (FR-952 "언어 설정은 영속되어야 한다")
컬럼만 있고 배선이 0건인 것을 실측으로 확인했다. 배선의 방향:
- 로그인·refresh 응답의 user에 `locale`이 실린다 → 클라가 LocaleStore에 **써서 덮는다**(서버 정본).
- 로그인 상태에서 언어를 바꾸면 `PATCH /me/locale` → 서버 갱신(실패해도 화면은 로컬 값 유지 —
  다음 로그인 때 서버 값이 이긴다는 것을 아는 채로 두는 트레이드오프).
- 비로그인은 지금처럼 로컬 저장소만.

### 1-5. clientCheck는 크랙 방지가 아니다 — 남용 억제다
NFR-308: 바이너리에 넣은 값은 비밀이 아니다. 그래서 이 검사의 목적은 "정품 클라이언트 증명"이
아니라 **아무 스크립트나 프로덕션 API를 긁는 비용을 올리는 것**이다. 웹 = Origin 화이트리스트,
데스크톱 = 빌드 시 주입되는 `x-vock-client` 헤더 대조. 로컬은 skip(C2.3 §0이 이미 그렇게
계약했다 — e2e가 이 전제 위에 서 있다).

## 2. 동작 규칙

| # | 규칙 | 근거 |
|---|---|---|
| DS2-1 | CORS는 env 주도다. `AppDeps.corsOrigins`가 없으면 미들웨어 자체가 안 붙는다(현행 무변화) | 웹 단일 오리진 배포(CloudFront)는 CORS가 필요 없다. 항상 붙이면 로컬·e2e까지 헤더 단정이 흔들린다. e2e는 Origin을 안 보내므로(실측) 붙여도 안 깨지지만, "안 붙는 게 기본"이 더 좁다 |
| DS2-2 | 프로덕션 오리진 허용 목록에 `https://tauri.localhost`·`http://tauri.localhost`·`tauri://localhost` 셋을 **후보로** 넣고, 실값은 S5 패키징 스모크에서 실측 확정한다 | 출처가 갈린다(§6 — Windows WebView2는 `http(s)://tauri.localhost`, 일부 문서는 `tauri://localhost`). 단정하지 않고 env로 좁힌다. dev는 vite 오리진(5185)이라 CORS 자체가 안 일어난다 |
| DS2-3 | clientCheck: `AppDeps.clientCheck` 미설정 = skip(로컬), 설정 시 비용 경로에서 웹 Origin 또는 데스크톱 헤더 중 하나를 요구. 실패 = 403. **남용 억제 수단이라는 성질을 코드 주석과 이 스펙에 못박는다** | §1-5. C2.3 §0 "로컬 skip" 계약 준수. 게이팅보다 앞에 둔다 — 카운터를 깎기 전에 거른다 |
| DS2-4 | `users.locale`: `UserRecord.locale` 필수 필드, `toUser` 매핑, `create` INSERT 포함, `UserRepository.updateLocale` 신설, `PATCH /me/locale`(Bearer 필수, `OutputLocale` 검증) | §1-4. 타입에 필수로 넣는 이유는 `getOutputLocale` 선례 — 선택이면 빠뜨린 곳이 조용히 ko 고정이 된다 |
| DS2-5 | `HttpApiConfig.platform`은 **필수**다. login 본문의 `platform` 하드코딩("web")을 이 값으로 바꾼다 | 같은 선례. 선택이면 데스크톱 셸이 빠뜨렸을 때 서버가 web 자격증명으로 교환을 시도하고, 그 오류는 Google 쪽 메시지로만 온다 |
| DS2-6 | 데스크톱 로그인 흐름: `redirectUri()` = 리스너 시작 후 `http://127.0.0.1:<port>` → `navigate` = 시스템 브라우저 열기 → `waitForCallback` = 콜백 URL 수신 → 기존 `readCallback`(state 검증 포함) → 기존 exchange. **리스너는 성공·실패·중단 모두에서 `cancel(port)`로 닫는다** | 계약 §140(루프백), 플러그인 README("must call cancel"). state 검증(A-4)은 경로가 달라도 동일하게 적용 |
| DS2-7 | 키링 저장 실패는 조용히 삼키지 않는다 — write-through 실패 시 콘솔 경고 1줄(개인정보 없이). 읽기 실패 = 로그아웃 상태로 기동 | §1-3의 트레이드오프를 아는 채로 운영하기 위한 최소 신호 |
| DS2-8 | `googleClientId` 부트 배선: local = `GOOGLE_CLIENT_ID` env(선택 — 없으면 버튼 없음, A-2 강등), aws = `secrets.google.web.clientId`(이미 스키마에 있음) | 브리핑 발견: 어느 부트도 안 채우고 있어 실 로그인 버튼이 뜰 수 없는 상태였다. e2e는 mock 주입이라 통과해 왔다 — 통과가 배선 존재를 증명하지 않는 실례 |
| DS2-9 | 실 Google 데스크톱 로그인의 완료 기준은 콘솔 등록(사용자) 후로 미룬다. S2의 기계 검증 = mock 서버로 `platform:"desktop"` 교환 관통 + 창에서 시스템 브라우저가 열리는 것까지 | 계약 §9 "웹/데스크톱 client_id 이원화의 콘솔 실등록 확인 — 실측으로 확정". 콘솔은 리포 밖이다 |

|---|---|---|
