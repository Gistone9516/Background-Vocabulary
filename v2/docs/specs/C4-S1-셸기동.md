# C4 S1 스펙 — 셸 기동 (Tauri 창에 같은 앱이 뜬다)

> 상위 = [C4-데스크톱.md](C4-데스크톱.md) (D-1·D-3·D-7·D-12가 이 슬라이스를 지배).
> 규칙: DS-1~DS-7 (7건)

## 0. 범위 / 비범위

- **포함**: 여정 배선을 `ui-shared`로 승격 · `packages/desktop`(Vite 진입 + `src-tauri`) 신설 ·
  게이트 등록(코드보다 먼저) · Tauri 창에서 로그인 전 여정이 도는 것까지.
- **제외**: 로그인(S2 — 이 슬라이스에서 데스크톱 로그인 버튼은 **뜨지 않는다**) · 보안 저장소(S2) ·
  오프라인 캐시(S3) · 파일첨부·알림·단축키(S4) · 패키징·서명(S5) · Linux(D-9).

## 1. 핵심 설계 결정

### 1-1. 여정 배선을 `ui-shared`로 올린다 — 다른 길이 없다
`web/src/deps.ts:2`의 약속("데스크톱 셸은 App.tsx를 그대로 두고 이 파일만 바꿔 끼운다")은
**App.tsx가 web 안에 있는 한 지킬 수 없다.** 형제 참조(`desktop → web`)는 게이트가 막고(SoT §7),
복사하면 여정이 두 벌이 되어 D-12(기획 동일선상)가 코드 차원에서 깨진다. 유일한 길은 승격이다:
`AppBody`(여정 배선)·`sidebarSlots`·`doneNotice`가 `ui-shared/src/app/`으로 올라가고, 셸에는
**ShellDeps 구현만** 남는다. ADR-004 P3("화면·훅은 ui-shared, 셸은 얇게")의 마지막 조각이다.

### 1-2. 로그인은 능력(capability)이다 (D-12의 첫 적용)
`ShellDeps`에 `auth: { redirectUri(): string } | null`을 더한다. `null` = 이 플랫폼은 아직 OAuth
능력이 없다 → 로그인 버튼이 뜨지 않는다(S5a A-2 "client_id 없으면 버튼 없음"과 같은 모양).
웹은 오늘의 `location.origin` 로직을 그대로 넘기고, 데스크톱은 S1에서 `null`, S2에서 시스템
브라우저+루프백으로 채운다. **화면 분기가 아니라 능력 유무다** — 화면은 한 벌 그대로다.

### 1-3. S1의 데스크톱 저장소는 임시이고, 임시임을 코드에 적는다
- 토큰: `memoryTokenStore`(ui-shared에 이미 있음). 로그인이 없으므로 충분하고, S2가 OS 보안
  저장소로 교체한다(D-5).
- 로케일: 웹의 localStorage 구현을 `ui-shared`의 `browserLocaleStore`로 승격해 **양쪽이 같은
  구현을 쓴다**(webview도 localStorage가 있다. `memoryTokenStore`가 ui-shared에 있는 선례).
  S2에서 `users.locale` 동기화가 붙으면 그때 재판단한다.

## 2. 동작 규칙

| # | 규칙 | 근거 |
|---|---|---|
| DS-1 | 게이트 등록이 첫 커밋 단위다: gate 체인에 `tsc --noEmit -p packages/desktop`, `PROMPT_ROOTS`에 `desktop/src`, `ALLOWED`·`ASSET_ALLOWED`에 `desktop` 키. 등록 직후 **일부러 어긴 코드로 실패를 확인**한다 | D-7. 통과만 보면 막는지 알 수 없다(S6에서 반복 실측) |
| DS-2 | 여정 배선 승격 후 **web의 화면 결과가 변하지 않아야 한다.** 빌드 + 실화면으로 확인한다 | §1-1은 이동이지 수정이 아니다. 이동에 수정이 섞이면 실패 시 원인을 못 가른다(work-rules-diagnosis) |
| DS-3 | 데스크톱 API 주소: dev는 vite 프록시 `/api`(`.env.development`에 **명시** — 폴백이 아니다), 프로덕션 빌드는 `VITE_API_BASE` 미설정 시 **vite 설정이 던져서 빌드가 깨진다** | D-3. dev에서 상대경로가 성립하는 이유는 Tauri dev가 vite 서버(같은 오리진)를 로드하기 때문이고, 프로덕션(`frontendDist`)은 오리진이 달라 CORS(S2) 전까지 실서버 통신이 안 된다 — 이 한계를 아는 채로 진행한다 |
| DS-4 | `adapters/tauri`는 S1에서 만들지 않는다 | S1에는 Tauri API를 쓰는 TS가 한 줄도 없다(토큰=메모리, 로케일=localStorage). 빈 스텁을 미리 만들지 않는 것은 C1 선례("5개만 실체화, 빈 스텁 미생성"). 첫 Tauri API가 등장하는 S2에서 만든다 — 상위 스펙 S1 행의 "adapters/tauri 신설"은 이 결정으로 **S2로 이동** |
| DS-5 | `src-tauri`(Rust)는 생성 골격 그대로 두고 손대지 않는다. 커스텀 커맨드 0개 | D-8(Rust에서 권한 판정 금지)을 지키는 가장 확실한 방법은 S1에서 Rust에 아무것도 안 넣는 것이다. `.rs`는 게이트 사각지대다 |
| DS-6 | `src-tauri/target/`은 커밋하지 않고 `Cargo.lock`은 커밋한다 | target은 수 GB 빌드 캐시. Cargo.lock은 앱(라이브러리 아님)이므로 재현 빌드의 정본이다 |
| DS-7 | 창 크기 기본 1200×800, 최소 800×600. 셸 반응형이 이미 이 범위를 다룬다 | C3 S1의 반응형 셸이 좁은 폭~와이드를 실측으로 검증했다. 데스크톱 창은 그 범위 안이다 |

```
desktop/                             [신규] package.json·tsconfig(web 미러)·vite.config(5185, D-3 검사)
  ├ index.html · src/{main.tsx,deps.ts,vite-env.d.ts}
  └ src-tauri/                       tauri init 골격 + conf(제품명 배경노트, 창 크기)

package.json                         gate 체인에 desktop 타입 검사

```

## 4. 검증 (2026-07-30 실측 결과 포함)

| 케이스 | 기대 | 결과 | 규칙 |
|---|---|---|---|
| desktop에 타입 오류를 넣고 gate | 실패 | ✅ exit 2 확인, 복원 후 통과 | DS-1 |
| desktop이 `@vock/core`를 import | 경계 게이트 실패 | ✅ exit 1, `역참조/허용밖 의존` 출력 | DS-1 |
| desktop/src에 프롬프트 토큰 | portability 실패 | ✅ exit 1 | DS-1 |
| 승격 후 web 빌드·실화면 | 이전과 동일 | ✅ CSS 번들 해시 동일(`CTGwNO9F`), 실화면 확인(진입·사이드바·언어 선택) | DS-2 |
| `VITE_API_BASE` 없이 desktop 프로덕션 빌드 | **빌드 실패** | ✅ exit 1 + D-3 메시지. 주입 시 빌드 성공도 확인 | DS-3 |
| Tauri 창 기동 | 진입 화면 + 로그인 버튼 **없음** | ✅ 창 캡처 실측(1200×800, 제목 배경노트). 진입 화면·사이드바·예시 칩·언어 선택기 렌더, 로그인 버튼 없음 | §1-2 |
| 창에서 여정(mock 서버) | 진입→좁히기 관통 | **△ 나눠서 증명.** 같은 vite 서버(5185)·같은 번들·같은 프록시로 진입→/classify→좁히기 1턴 관통을 Playwright로 확인. **창 안에서의 입력 자동화는 실패** — `SetForegroundWindow`가 True여도 SendKeys가 WebView2에 닿지 않았다(OS 입력 자동화의 한계, 두 방식 시도). 창이 그 번들을 띄운다는 것은 캡처로 증명됐으므로 남은 간극은 "WebView2 안에서의 실입력"뿐이다 — 사용자가 기기 앞에 있을 때 창에서 직접 한 턴 돌려 보는 것이 정확한 마감이다 | DS-3 |

## 5. 열린 항목

- **번들 identifier.** `tauri.conf.json`에 역도메인이 필요하다. `kr.co.bewe.vocknote`로 두었다 —
  도메인 정본이 정해지면 사용자 확인으로 바꾼다(설치 후 바꾸면 다른 앱으로 취급되므로 S5 전 확정).
- **앱 아이콘.** tauri 기본 아이콘으로 시작한다. 랜딩 파비콘(S6 열린 항목)과 같은 디자인 결정이다.
- ~~폰트 내장(D-10)~~ → **해소(S3).** 그리고 내장하며 실측으로 발견: CDN CSS의 패밀리 이름
  (`Pretendard Variable`)을 참조하는 곳이 0곳이라 **웹폰트가 로드된 적이 없었다** — tokens.css
  스택 선두에 추가해 웹·데스크톱 둘 다 처음으로 실제 Pretendard로 그려진다. `C4-S3` §1-4.
