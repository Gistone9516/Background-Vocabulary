# C5 S2 스펙 — 프라이머 종착 화면 (승계원장 d-4 · SoT §3에서 파생)

> 앞 = [C5-S1](C5-S1-조회저장과상세영속.md) · [C3-S4b](C3-S4b-프라이머.md). 뒤 = C5-S3 재방문 카드(d-2) · C5-S4 마인드맵(FR-312).
> 규칙: T-1~T-15 (15건)

## 0. 범위

- **포함**: 여정에 종착 칸 신설 · 담기 화면에서 프라이머 분리 · 선택 집합 기반 조립 · 우측 패널(스코프 1·2) · 좁은 화면 FAB + 바텀시트 · 배경 브리핑 규칙 블록 · **`primer_ask` 문구 교정(사전 기조, T-15)** · 조회 목록 조회 API(S1이 미룬 소비자가 여기 온다).
- **제외**: 마인드맵 패널 본체(S4가 능력을 꽂는다) · 재방문 능동 카드(S3) · FR-605 공유 링크 · FR-606 딥링크(보안 설계 선행, SRS §7-13) · 프라이머 본문 자유 편집(T-3).

## 1. 왜 이 화면이 필요한가

승계원장의 진단은 **세션 이후가 비어 있다**는 것이고, 그 앞단에 이 문제가 있다.

> "이 제품의 **유일한 핵심 전환점**은 담은 걸 실제로 메인 AI에 붙여넣어 쓰는 행동이다. … 그런데 현재 구조에선 이 붙여넣기 요약이 여러 기능 중 하나로 묻혀 있어, 사용자가 '이제 뭘 하지?'에서 멈출 수 있다." [12d-7, 등급 4]

v2도 같은 구조다 `[코드]` — `usePrimer`가 `KeptScreen` 안의 한 기능이고, 프라이머 블록은 담은 목록 **아래**에 조건부로 붙어 담은 게 많을수록 스크롤 밑으로 밀린다. 세션의 출구는 `onBackToTerms`와 `onHome` 둘뿐이라 **되돌아가는 문만 있고 나가는 문이 없다.**

목표 상태는 한 문장이다: **사용자가 표현 비용을 한 번도 지불하지 않은 채, 완성된 프롬프트가 손에 쥐어진 상태로 세션이 끝난다.**

**우측 패널 스코프 3단** (사용자 확정 2026-07-31)

| 스코프 | 범위 | 출처 |
|---|---|---|
| 1 | 이번 세션에서 조회·저장한 어휘 | `details`(세션 스코프, 신규 조회 API) + `assets` |
| 2 | 프로젝트·전체 자산 | `GET /assets` — **이미 있다.** 새 엔드포인트를 만들지 않는다(T-9) |
| 3 | 마인드맵 확장 패널에서 블록 선택 | S4가 능력을 꽂는다. 이 슬라이스에서는 `null`(T-4) |

## 2.5 배경 브리핑 규칙 블록 (초안 — 레드펜 대상)

```
[배경 브리핑 — 배경노트]
아래는 참고 자료입니다. 질문이 아닙니다.
· 사용자는 이 어휘들을 인지하고 있습니다 — 외운 것이 아니라 필요할 때 찾아보는 사전입니다.
· 이 수준을 기준으로 진행 중인 작업의 깊이를 맞춰 주세요.
· 작업의 방향은 바꾸지 마세요.
```

**현행 문구를 교정해야 한다.** 지금 프라이머의 핵심 한 줄은 `primer_ask` = "아래 어휘는 **이미 알고 있다고 두고** 답해 주세요"이고, 이것은 숙달 전제라 T-15와 어긋난다. 기본 정리와 AI 정리가 **둘 다** 이 키를 쓰므로(`primer.ts`), 교정하면 두 경로가 함께 바뀐다. 4개 로케일은 `AUTHORED` 경유(T-11).

교정 방향은 **금지에서 보정으로**다. "설명하지 마라"(하지 말 것)만 있으면 메인 AI가 어느 수준으로 가야 하는지 모른다. "이 수준에 맞춰라"(할 것)를 주면 깊이가 정해진다.

## 3. 동작 규칙

| # | 규칙 | 근거 |
|---|---|---|
| T-1 | 종착은 여정의 칸이다(`journey.at === "primer"`). 담기 화면은 목록 관리만 하고 프라이머 미리보기를 갖지 않는다 | 두 화면이 같은 본문을 보이면 어느 쪽이 진짜인지 흐려진다. 종착은 화면 안의 상태가 아니라 여정의 위치다 |
| T-2 | 복사 본문은 **화면이 보여준 선택 집합에서만** 나온다. 문자열 조립은 `primer.ts`를 그대로 쓰고 인자만 선택 집합으로 바꾼다 | 화면과 클립보드가 어긋나면 이 제품에서 가장 나쁜 버그다 — 사용자가 확인할 방법이 없다. 조립 함수를 하나로 두면 어긋남이 표현 불가능해진다(DG-3) |
| T-3 | 편집은 **블록 추가·제거뿐**이다. 본문 자유 입력칸을 두지 않는다 | 사용자 확정 2026-08-03(A). 마지막 단계에서 자유 입력이 주 경로가 되면 표현 비용을 되돌려주는 셈이라 §2.1과 13-12를 배신한다 |
| T-4 | 스코프 3은 능력이다. `mapPanel: MapPanel \| null`이 `null`이면 그 절이 뜨지 않는다 | `ShellDeps.auth`(C4-S1)·`offline`(C4-S3) 선례. 나중에 여정을 고치지 않고 꽂을 자리를 지금 비워 둔다 |
| T-5 | 좁은 화면 FAB은 **'이대로 복사'가 뷰포트에 걸릴 때만** 뜬다(끄트머리라도). **넓은 화면에서는 뜨지 않는다** | 사용자 확정 2026-08-03. 가시성이 트리거라 브레이크포인트가 필요 없고, 프라이머를 훑는 중에는 안 떠서 방해가 없다. 넓은 화면에는 우측 패널이 이미 있어 FAB을 더하면 같은 일을 하는 진입점이 둘이 된다 |
| T-6 | 바텀시트와 우측 패널은 **같은 컴포넌트**를 쓴다. 배치만 다르다 | D-12. 두 벌이면 한쪽만 고쳐져 갈라지고, 컴파일은 계속 된다 |
| T-7 | 배경 브리핑 규칙 블록이 복사 본문 맨 앞에 붙는다. **어휘를 "인지하고 있다"로 전달하고, 그 수준에 맞춰 깊이를 잡으라고 지시한다** | 두 가지를 동시에 막는다. ①프라이머가 "질문"으로 오독되는 것 — 지금은 맨 목록이라 메인 AI가 목록 자체에 반응할 수 있다. ②**숙달로 오독되는 것** — 담기는 학습 완료가 아니라 사전에 꽂아 두는 행위다(T-15). 재설명 금지는 FR-604·P-4이되, 그 이유가 "다 외웠으니까"가 아니라 "찾아보면 되니까"다 |
| T-8 | 조회 목록 조회는 `body`를 뽑지 않는다 | C5-S1 E-8. 대형 JSONB, Data API 1MB 상한. 여기서 그 규칙의 소비자가 처음 생긴다 |
| T-9 | 스코프 2는 `GET /assets`를 쓴다. 자산 목록 엔드포인트를 새로 만들지 않는다 | 커서 페이지네이션까지 이미 있다. 두 번째 목록 API는 같은 질문에 구현이 둘이 되는 것이다 |
| T-10 | 종착 화면 진입은 담기 화면의 주 버튼이다. 담기 수로 자동 전환하지 않는다 | 계속 담고 싶은 사용자를 끊는 것이 오히려 마찰이다 |
| T-11 | 규칙 블록 문구는 `strings.ts`(ko)에 두고 나머지 로케일은 `port-i18n.mjs`의 `AUTHORED`를 거친다 | 손편집하면 이식분/작성분 구별이 사라진다(`strings.ts.md` 판단 3-b). 문구 자체는 레드펜 대상이다 |
| T-12 | 복사 성공 뒤 세션이 끝났다는 확인을 보인다. 그 자리는 S3(재방문 카드)·S4(마인드맵)가 채울 자리로 비워 둔다 | 종료 신호가 없으면 "이제 뭘 하지"가 그대로 남는다. 다만 지금 채우면 S3의 결정을 앞질러 정한다 |
| T-13 | 화면을 열었을 때 **저장(담기)한 어휘는 기본 포함**, **조회만 한 어휘는 기본 미포함**이다. 둘 다 패널에서 넣고 뺄 수 있다 | 담기는 "내 작업에 필요하다"는 명시적 판단이고 조회는 "찾아봤다"까지다. 기본값을 행동의 세기에 맞추면 사용자는 대개 아무것도 안 해도 된다 — 판단 0회가 목표다 |
| T-14 | 어휘 줄의 순서는 카드의 `priority` 순이다. 클릭 순서가 아니다 | 클릭 순서로 하면 **같은 어휘 집합인데 조작 이력에 따라 붙여넣는 글이 달라진다.** priority는 카드가 이미 갖고 있고, 메인 AI에게도 중요한 것이 앞에 오는 편이 낫다 |
| T-15 | ★**이 어휘 자산은 사전이지 학습 이력이 아니다.** 담기·조회 어느 것도 "학습 완료"를 뜻하지 않으며, 프라이머 문구·패널 문구·향후 모든 기능 문구가 이 전제를 어겨서는 안 된다 | 사용자 확정 2026-08-03: "이 배경어휘는 사전이라 생각해야 해. 블록을 저장한다고 사용자가 100% 학습한게 아니야. 두고두고 계속 보는 사전이지." 어기면 제품이 학습 도구로 미끄러지고, 그 순간 NotebookLM·Study Mode의 본진에서 싸우게 된다(12d-6·12d-14) |

## 4. 계약 변경

**조회 목록 조회** — S1이 소비자 없이 만들지 않으려고 미뤄 둔 것이 여기서 생긴다.

```
DetailRepository.listBySession(userId, sessionId): Promise<DetailSummary[]>
DetailSummary { term_norm, created_at }      // body 없음(T-8)
GET /sessions/:id/viewed                      // 소유권 대조는 기존 CRUD 규약 그대로
```

`term_norm`만으로는 화면에 이름을 못 쓰므로, 표시용 이름은 세션의 `generated`에서 잇는다(`SessionRec.generated`가 카드 전체를 이미 보존한다, FR-702). 서버가 이름을 또 저장하면 같은 값에 출처가 둘이 된다.

## 7. 검증

| 케이스 | 기대 |
|---|---|
| 블록 클릭 | 선택 집합에 추가, 복사 본문에 그 어휘가 생김 (T-2) |
| 포함 리스트 제거 | 선택 집합에서 빠지고 복사 본문에서도 사라짐 |
| 화면과 클립보드 | 같은 선택 집합에서 나온다 — 어휘 집합이 일치 (T-2) |
| 선택 0개 | 복사 버튼이 눌리지 않거나 안내. 빈 본문을 복사시키지 않는다 |
| `mapPanel: null` | 스코프 3 절이 렌더되지 않음 (T-4, 음성) |
| 규칙 블록 | 본문 맨 앞. "설명"을 요구하는 문장이 없다 (T-7, 음성) |
| 사전 기조 | 본문 어디에도 학습·숙달·암기를 뜻하는 말이 없다 (T-15, 음성) |
| 초기 선택 집합 | 저장한 어휘만 들어가 있고 조회만 한 것은 빠져 있다 (T-13) |
| 어휘 줄 순서 | priority 오름차순. 클릭 순서를 바꿔도 본문이 같다 (T-14) |
| 조회 목록 응답 | `body` 미포함 (T-8) |
| 담기 화면 | 프라이머 본문이 더 이상 없다 (T-1, 음성) |

FAB 표시 조건(T-5)은 뷰포트 가시성이라 노드 e2e로 못 본다 — **사용자 시각 확인 대상**이다.

## 8. 열린 항목

- **FAB·시트는 기계 검증이 없다.** 가시성·제스처는 브라우저 안에서만 판정된다. 좁은 화면 실측은 사용자 확인으로 마감한다.
- **규칙 블록 문구는 초안이다.** 랜딩 카피 선례대로 레드펜 대상이며, 특히 "배경노트"를 밝히는 것이 브리핑 선언으로서 기능하는 범위를 넘어 브랜드 노출이 되면 12d-3 원칙(두 핵심 이유에 기여하는 것만)에 안 걸린다.
- **T-12의 종료 확인이 무엇을 보일지는 S3에서 정한다.** 지금 채우면 재방문 카드의 설계를 앞질러 정하게 된다.
