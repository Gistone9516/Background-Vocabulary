# C4 S5 스펙 — 패키징 (서명 없는 설치 파일까지. 서명·업데이터는 인증서 결정 뒤)

> 상위 = [C4-데스크톱.md](C4-데스크톱.md) (D-9·완료 기준 "서명 없는 업데이터가 켜져 있지 않다").
> 웹 근거(2026-07-30): v2 업데이터는 NSIS·MSI 둘 다 지원(§5). 규칙: DS5-1~DS5-6 (6건)

## 0. 범위 / 비범위

- **포함**: Windows 설치 파일(NSIS, 무서명) 산출 · 설치 스모크 · **프로덕션 웹뷰 Origin 실측**
  (DS2-2가 이 슬라이스로 미룬 것) · DEPLOY.md 데스크톱 절.
- **비범위·대기**: **코드 서명 + 업데이터(FR-905)** — 인증서 지출 결정(사용자, OV 연 $200~300)
  뒤에 한 슬라이스로. FR-905와 NFR-604는 쌍이므로 **서명 없는 업데이터는 켜지 않는다**(완료 기준
  원문). Linux 패키징 — D-9(빌드 호스트 없음). ADR 권고(AppImage 주 + deb 보조)는 기록만.

## 1. 핵심 설계 결정

### 1-1. Windows 형식 = NSIS 단일, per-user 설치
업데이터 호환은 NSIS·MSI 동률이다(웹 근거). 가른 것은 설치 권한이다 — NSIS 기본은 per-user
(`%LOCALAPPDATA%`, **관리자 불필요**), MSI는 per-machine 계열. 이 세션이 직접 실측한 제약이
근거다: 원격 제어 중에는 UAC 승인이 불가능했다(S2 툴체인 설치에서 겪음). 사용자가 관리자 승인
없이 설치·업데이트할 수 있는 형식이 이 제품의 배포 현실에 맞다. `targets`를 `"nsis"`로 명시한다
— `"all"`은 결정을 미룬다는 뜻이고, 형식이 자동 업데이트·권한을 좌우한다고 SRS `:263`이 못박았다.

### 1-2. 스모크는 로컬 mock을 향해 빌드한다 — 그리고 Origin을 실측한다
프로덕션 번들은 `VITE_API_BASE` 주입이 강제다(D-3 — 미설정이면 빌드가 깨진다, S1 실측).
스모크 빌드는 `http://127.0.0.1:8787`(로컬 mock)을 주입한다. 설치된 앱의 웹뷰 오리진은
API와 다른 오리진이므로 **CORS가 실제로 강제되는 첫 환경**이다 — dev(vite 프록시)에서는
한 번도 강제된 적이 없다. 부트 시 /config 요청이 어차피 나가므로(응답 차단과 무관하게 요청은
도달한다) 서버 쪽에서 Origin 헤더 실값을 채집해 DS2-2의 후보 셋을 실값 하나로 좁힌다.

### 1-3. identifier·productName은 여기서 확정된다
설치 후 바꾸면 다른 앱으로 취급된다(S1 열린 항목이 "S5 전 확정"으로 예고). 현행 유지로 확정:
`kr.co.bewe.vocknote`(사용자 도메인 bewe.co.kr 역순) / `vock-note`(바이너리·설치명은 ASCII —
표시 이름 "배경노트"는 창 제목이 갖는다). 바꾸려면 이 슬라이스가 마지막 기회였다.

## 2. 동작 규칙

| # | 규칙 | 근거 |
|---|---|---|
| DS5-1 | 이 슬라이스의 산출 = **무서명 NSIS 설치 파일 + 설치 스모크**. 업데이터 설정은 넣지 않는다 | 완료 기준 "서명 없는 업데이터가 켜져 있지 않다". 켜 두고 서명만 미루면 그 사이의 모든 설치본이 무결성 검증 없는 업데이트 채널을 갖는다 |
| DS5-2 | `bundle.targets = ["nsis"]` 명시 | §1-1. 형식은 선결 변수다(SRS :263) |
| DS5-3 | 스모크: 조용한 설치(/S) → 설치 경로에 exe 실재 → 기동 → 창 렌더 캡처 → 퀵 캡처 동작 | "설치 파일이 나온다"만으로는 설치가 되는지 모른다. 무서명이라 SmartScreen 경고는 예상 동작이다(인증서 결정의 근거 자료) |
| DS5-4 | Origin 실측값으로 `VOCK_ALLOWED_ORIGINS` 문서(DEPLOY.md)를 후보 셋에서 실값으로 좁힌다 | DS2-2가 이 슬라이스로 미룬 실측. 단정 대신 측정 |
| DS5-5 | 빌드 명령·주입 env·산출 경로를 DEPLOY.md에 적는다 — 재현 가능해야 배포다 | 다음 사람(다음 세션)이 같은 설치 파일을 만들 수 있어야 한다 |
| DS5-6 | 서명·업데이터 슬라이스의 선행 조건을 명시해 둔다: OV 인증서(사용자 지출 결정) → signing 설정 → updater 엔드포인트·공개키 → FR-905 완료 | 대기 항목이 문서에 없으면 "됐다"와 "미뤘다"가 섞인다 |

## 3. 검증 (2026-07-30 실측 결과)

| 케이스 | 기대 | 결과 |
|---|---|---|
| 첫 프로덕션 빌드 | — | ❗vite 기본 타깃(es2020)이 최상위 await(키링 선로드)를 거부 — dev는 통과라 빌드에서야 드러났다. `build.target: "es2022"`로 해소(웹뷰는 WebView2 하나라 낡은 타깃을 지킬 이유가 없다) |
| 주입 후 `tauri build` | NSIS 산출 | ✅ `vock-note_0.1.0_x64-setup.exe` 4.1MB(release 4m12s) |
| 조용한 설치(/S) | per-user·관리자 불요 | ✅ `%LOCALAPPDATA%\vock-note`, HKCU 언인스톨 등록, exit 0 |
| 설치본 기동 | 창 렌더 | ✅ 캡처 — 진입 화면·첨부 잠금 버튼(S4 산출)까지 렌더 |
| 부트 /config의 Origin | 실값 채집 | ✅ **`http://tauri.localhost`** (에코 서버 채집 — 후보 셋이 실값 하나로) |
| 채집값 CORS + curl | ACAO 반환/타 Origin 거부 | ✅ 양방향 증명. ★도중 함정: 에코(127.0.0.1 바인드)와 mock(:: 바인드)이 **같은 포트에 공존**해 curl이 에코를 치고 있었다 — "코드가 아니라 토폴로지"가 원인인 실패의 표본 |
| 설치본 Ctrl+Shift+K | 복원 | ✅ release 빌드에서도 최소화→복원(Rust 핸들러) |
| SmartScreen | 경고 기록 | △ **로컬 빌드 파일은 MOTW가 없어 안 뜬다** — 실배포(다운로드) 경로 실측은 불가였다. 무서명 비용의 실측은 웹 배포 후로 |

`VITE_API_BASE` 부재 시 빌드 실패는 S1에서 음성 실측했고 이번 흐름의 es2020 실패가 같은 vite
게이트 단계에서 일어나 경로 자체가 살아 있음을 재확인했다(별도 재실행은 생략 — dist 경합 회피).

## 4. 열린 항목

- **서명 + 업데이터** — 인증서 결정(사용자) 후 별도 슬라이스. 선행 조건 목록은 DS5-6.
- **Linux 패키징** — 빌드 호스트(2단계 인프라 목표와 연동) 후. AppImage 주 + deb 보조(ADR-001).
- **SmartScreen 경고 실측 기록** — 무서명 배포의 실제 UX 비용. 인증서 지출 판단의 근거 자료로 스모크에서 기록.
